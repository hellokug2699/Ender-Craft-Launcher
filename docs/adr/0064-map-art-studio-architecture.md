# ADR 0064: Map Art Studio Architecture

- Decision: Proposed
- Implementation: Not Started
- Date: 2026-11-08
- Scope: Map Art Studio Addition、地图画画布、单张与多地图拼接、图片与地图数据导入、地图颜色映射、材料规划及可选投影预览组合
- Related: [ADR 0032](0032-native-feature-interfaces-and-optional-additions.md)、[ADR 0053](0053-addition-capability-permission-and-user-consent.md)、[ADR 0054](0054-addition-registry-and-manifest-governance.md)、[ADR 0055](0055-ecl-hybrid-workspace-and-native-tool-platform-architecture.md)、[ADR 0060](0060-multi-addition-visual-preview-composition.md)、[ADR 0063](0063-ecl-player-workspace-architecture.md)

## 背景

地图画制作同时涉及图像处理、Minecraft 地图颜色规则、目标画布尺寸、材料选择和建造规划。它与 Schematic Preview 存在有价值的组合场景，但两者处理的核心数据不同：

- Map Art Studio 以二维图像、像素、地图颜色、地图区域和材料映射为核心。
- Schematic Preview 以三维结构、方块位置、结构解析和空间预览为核心。

若将地图画能力作为 Schematic Preview 的子功能，会使只想从图片制作地图画的用户承担不必要的扩展依赖，也会混淆二维颜色规划与三维结构预览的职责。

此外，地图画并不只有“将图片缩放到一张地图”这一种场景。用户可能指定画布尺寸并拼接多张地图；尺寸会改变可用空间、细节保留、渐变表达和材料优化结果。用户也可能导入已经存在的 Minecraft 地图数据，但地图数据中的颜色不能唯一反推出原始方块、材质或建造过程。

## 决策

### 1. 建立独立的 Map Art Studio Addition

将 ECL Map Art Studio 作为独立 Feature Addition 提议登记：

- Name：Map Art Studio
- Addition ID：`ecl.map-art-studio`
- Type：`Feature`
- Registry Status：`Proposed`

Map Art Studio 可以独立完成画布创建、图像处理、地图颜色映射、材料分析和方案导出。Schematic Preview、Player Workspace、Resource Pack Studio 或其他能力均不得成为其基本功能的强制依赖。

### 2. 使用统一画布模型支持单张与多地图

单张地图与多地图拼接属于同一画布模型，不应实现为两套互不兼容的项目类型。

- 单张地图是仅包含一个地图区域的画布。
- 多地图画布由多个地图区域组成，支持明确的行列布局和区域级查看。
- 画布应区分整体画布尺寸、地图区域布局、地图缩放级别及最终建造结构尺寸；这些概念不可混为一个尺寸参数。
- 画布可以表达未分配、缺失或尚未确认的地图区域，不得将空白区域自动解释为纯色内容。
- 材料需求应能按整个项目汇总，也能按地图区域、颜色和材料类型拆分。
- 导入地图集合时，不得仅凭文件名或导入顺序断言地图相邻关系；只有具备可信的位置、地图身份或用户确认依据时，才可自动建立拼接关系。无法确定时应保留独立地图并允许用户整理布局。

原生 Minecraft 地图通常具有固定的像素网格；地图缩放级别决定其覆盖的世界范围。地图画布的地图数量、地图缩放级别、地图像素分辨率与建造所需方块结构尺寸应分别表达，不能假定“地图张数”可以直接等同于建造方块尺寸。

### 3. 支持不同来源进入统一画布

至少保留两类独立导入来源：

- **图片导入**：读取用户提供的图像，经过尺寸适配、图像分析和颜色映射后生成画布方案。
- **Minecraft 地图数据导入**：从可识别的原生地图数据中还原地图实际保存的像素颜色及可读取元数据，再进入统一画布。

两类来源最终进入统一画布、预览、材料分析和导出体系，但必须保留来源信息及处理历史。导入原生地图数据时，应尽可能读取地图身份、缩放级别、中心/覆盖范围、维度或其他可用元数据；实际可用字段取决于来源格式和版本，不得假定所有文件都包含完整空间信息。

### 4. 明确反向导入的证据边界

地图数据反向导入首先是**像素与地图内容还原**，不是自动恢复原始图片、原始材料或原始建造方案。

必须区分以下信息：

- **直接读取事实**：文件中实际保存的像素颜色、可读取的地图元数据和来源信息。
- **规则推导结果**：基于明确的 Minecraft 版本及已知地图颜色规则计算的结果。
- **候选推测**：可能产生相应地图颜色的方块、材料或建造方式。
- **未知信息**：缺少足够证据，无法可靠判断的内容。

地图颜色不能唯一确定原始方块。相同或相近的地图颜色可能由多个方块、不同方块状态或不同环境条件产生；模组还可能引入额外方块及自定义地图颜色行为。因此，材料识别必须允许多个候选和未知结果，不得将候选伪装成原始材料事实。

反向识别必须考虑目标 Minecraft 版本、地图颜色与明暗规则、生物群系影响、模组方块及其地图颜色行为等因素。材质包和光影通常影响屏幕渲染外观，并不等同于原生地图数据中保存的颜色来源；若导入的是截图而非原生地图数据，则材质、光影、显示环境、截图压缩和后处理均可能引入额外颜色偏差。两类来源必须采用不同的证据和置信度表达。

Resource Pack Studio、Shader Studio 或模组环境信息可以在未来作为可选辅助证据，但不得成为基础像素还原的强制依赖，也不得声称仅凭材质包或光影就能恢复地图的原始建造材料。

### 5. 将用户尺寸作为联合优化约束

用户指定的画布尺寸是核心输入约束，不只是导出时的缩放参数。系统应根据目标尺寸评估主体识别度、细节保留、颜色误差、渐变表现和材料需求。

规划中应区分：

- 地图区域数量与拼接布局；
- 地图缩放级别及其世界覆盖范围；
- 画布像素分辨率；
- 目标建造结构的空间尺寸。

尺寸较小时，应优先保护主体、轮廓和重要细节，避免为了追求渐变而造成结构或文字失真。尺寸较大时，可以利用更多空间表达细节和颜色过渡，但不得假定增加尺寸必然改善所有图像或降低材料成本。

尺寸质量预估应帮助用户比较不同尺寸方案。评估指标至少可以涵盖主体识别度、细节保留、颜色误差、渐变表现、材料种类和材料总量；具体评分方法和阈值留待原型验证，不在本 ADR 中写死。

### 6. 采用可组合的颜色映射与材料优化方向

颜色映射不应仅以 RGB 最近邻作为唯一策略。规划至少考虑：

- **Direct Mapping**：为目标像素选择可用地图颜色中最接近的候选，适合需要保持边缘、文字和局部色块的区域。
- **Dithered Mapping**：通过空间分布相邻颜色表达有限调色板难以直接呈现的中间色，适合在有足够空间时改善渐变。
- **Adaptive Mapping**：结合区域内容，在渐变、纹理、轮廓和细节区域采用不同映射倾向。

材料优化应同时考虑地图最终显示颜色、可用方块集合、版本和环境规则、材料种类/数量限制以及用户指定的偏好。用户可比较视觉优先、材料成本/种类优先等不同目标；系统应呈现方案之间的取舍，而不是宣称存在脱离约束的唯一最佳方案。

地图颜色映射必须考虑 Minecraft 地图颜色及其明暗/采样规则。具体可用颜色和映射结果可能受版本、方块、方块状态、生物群系、位置或其他游戏规则影响。若无法可靠模拟某种环境行为，应明确标记近似或未知，不得伪装成精确游戏结果。

### 7. 与 Schematic Preview 采用可选组合关系

Map Art Studio 与 Schematic Preview 是独立 Addition：

- Map Art Studio 负责图像/地图画布、颜色映射、材料分析和地图画规划。
- Schematic Preview 负责三维结构的读取、组织和空间预览。
- Map Art Studio 不依赖 Schematic Preview 才能生成或分析地图画方案。
- 在具备兼容的结构表达和受控协作能力时，可以将地图画方案转换或提供给 Schematic Preview 进行三维结构预览；具体转换能力、结构语义和支持范围须经原型验证。
- 组合时遵循 ADR 0060、ADR 0053、ADR 0054 与 ADR 0055。Addition 之间不得直接 IPC、共享私有对象或绕过 Core 的资源与权限边界。
- 不得因为支持与 Schematic Preview 组合，就将 Map Art Studio 改为其子扩展或建立强制安装依赖。

材料清单可以在获得用户授权后导出或交给 Player Workspace 管理；这属于可选集成，不要求 Player Workspace 存在。

### 8. 保留可解释的预览与导出边界

预览和导出结果应说明它们代表什么：图片像素方案、原生地图数据还原、颜色映射结果、材料候选或经过验证的建造结构。不同结果不得混用名称或暗示相同确定性。

导出能力可以逐步支持图像、材料清单、地图区域规划及受支持的结构格式。任何结构导出都必须标明目标版本、缩放/空间假设、材料映射和未解决限制；不得把视觉方案直接宣称为可在所有世界环境中无差异复现的建造指令。

## 备选方案

### 方案一：将地图画功能作为 Schematic Preview 的子功能

优点是可以直接围绕三维结构预览组织功能。

缺点是图片到地图画方案本身不需要投影解析；强制依赖会使独立用途受限，也会混淆二维像素/颜色规划与三维结构预览的职责。

不采用。保留独立 Addition，并提供可选组合。

### 方案二：只支持图片导入，不处理已有地图数据

优点是初期数据来源简单，避免处理地图身份、版本和空间关系。

缺点是无法分析玩家已有地图画，也失去像素还原和地图整理场景。

不作为长期架构限制。地图数据导入纳入产品方向，但其反向识别能力必须遵守证据边界，并可分阶段验证。

### 方案三：从地图颜色直接推断唯一方块

优点是输出简单，容易生成看似完整的材料清单。

缺点是地图颜色并非方块身份的唯一编码，模组、生物群系、版本、方块状态和环境规则会造成歧义；这种做法会把猜测伪装成事实。

不采用。输出候选、来源和不确定性。

### 方案四：固定单张地图或固定尺寸

优点是简化画布、材料统计和预览。

缺点是限制大型地图画，也无法利用用户指定尺寸改善细节和渐变表达。

不采用。单张地图作为统一多地图画布的一个特例。

## 后果

### 正面影响

- Map Art Studio 可以独立服务于图片转地图画，不要求用户安装 Schematic Preview。
- 单张与多地图拼接共用统一画布，减少重复模型和功能割裂。
- 用户可以在尺寸、视觉质量和材料成本之间进行明确权衡。
- 原生地图数据导入能够用于像素还原和地图整理，而不虚构原始建造信息。
- 可选组合使地图画方案能够进入三维结构预览和玩家工作空间，同时保持 Addition 独立生命周期。

### 成本与风险

- 不同 Minecraft 版本、地图颜色规则、生物群系和模组行为会扩大映射验证范围。
- 原生地图数据格式和来源环境可能不完整，地图身份与拼接关系未必能自动恢复。
- 截图导入存在渲染、色彩空间、压缩和后处理误差，不能与原生地图数据使用同一置信度。
- 渐变抖动和自适应映射需要在颜色误差、空间纹理、主体识别度与材料复杂度之间权衡。
- 多地图画布和材料规划可能产生较大的像素数据、候选集合和计算任务，需要按需处理和资源预算。
- 从二维地图画方案转换为三维结构涉及地图缩放、空间范围、方块布局和环境规则，必须经过独立验证。

### 待验证事项

- 目标版本原生地图数据的读取覆盖、地图身份和空间元数据可用性。
- 不同版本、生物群系和模组方块对地图颜色的影响范围及可验证数据来源。
- 地图缩放级别、地图区域拼接与实际建造空间尺寸之间的准确映射。
- 不同抖动算法和自适应映射策略在真实地图画样本上的视觉效果。
- 视觉优先与材料优先优化的可解释性、计算成本和用户可控性。
- Map Art Studio 与 Schematic Preview 之间可安全、无强制依赖的结构交换边界。

## 验收标准

本 ADR 当前为 Proposed。以下是未来实现评审的架构验收方向，不表示功能已经实现：

1. Map Art Studio 作为独立 Feature Addition 登记，稳定 ID 为 `ecl.map-art-studio`。
2. 不安装 Schematic Preview 时，Map Art Studio 仍可完成其独立画布、颜色映射和材料分析工作。
3. 单张地图与多地图拼接使用统一画布语义；材料统计可整体汇总并按地图区域拆分。
4. 画布尺寸、地图数量/布局、地图缩放级别、像素分辨率和建造结构尺寸不会被混为同一个参数。
5. 图片导入与原生地图数据导入能够区分来源；原生地图数据导入至少可在受支持格式内还原实际保存的像素颜色。
6. 无法确定地图空间关系时，不会仅凭文件名或导入顺序自动断言地图相邻关系。
7. 系统区分直接读取事实、规则推导、候选推测和未知信息；不把地图颜色对应关系伪装成原始方块身份。
8. 截图导入与原生地图数据导入采用不同的误差和证据说明，不将材质包或光影外观误认为原生地图颜色数据。
9. 用户指定尺寸会参与质量预估和方案优化；尺寸变化可体现对细节、主体识别度、渐变表现和材料需求的影响。
10. 颜色映射不局限于 RGB 最近邻，并能在受支持范围内比较直接映射、渐变抖动或自适应策略。
11. 材料分析支持多个候选和用户约束，不将无法确定的材料标记为确定结果。
12. 多地图材料需求可整体汇总，并能按区域、颜色或材料类型查看。
13. 与 Schematic Preview 的集成是可选组合，遵循 ADR 0060 和 Core 受控协作边界；任一 Addition 缺失不破坏另一方独立能力。
14. 导出结果明确区分像素方案、材料候选和经过验证的结构数据，不夸大其可复现性。
15. Addition 注册表、单项 README、Manifest 与本 ADR 对 Addition ID、名称、类型和状态保持一致。
