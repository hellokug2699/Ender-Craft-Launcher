# ADR 0040：原版工具集作为独立官方 Addition

- Decision: Accepted
- Implementation: In Progress
- Date: 2026-11-02
- Scope: 面向 Minecraft 原版规则的轻量查询、计算、模拟与辅助工具，以及其官方 Addition 交付、版本化数据接口和数据模板
- Related: [ADR 0032：原生功能入口与按需 Additions 扩展体系](0032-native-feature-interfaces-and-optional-additions.md)、[ADR 0033：本地 Minecraft 全面诊断与知识引擎](0033-local-minecraft-diagnostic-and-knowledge-engine.md)、[ADR 0035：离线 Minecraft 知识库](0035-offline-minecraft-knowledge-library.md)、[ADR 0036：内置浏览器与 Minecraft 知识访问](0036-embedded-browser-for-minecraft-knowledge.md)

## 背景

玩家在游玩 Minecraft 时，经常需要快速确认某个版本的指令语法、查询注册表 ID、计算附魔结果、查看矿石生成分布、确认配方或理解某项原版机制。现有做法通常要求玩家离开 ECL，使用搜索引擎、Wiki 或外部计算器；这些资料可能混杂不同游戏版本，查询结果也需要玩家自行判断适用范围。

这些需求具有共同特点：功能范围小、目标明确、结果可结构化表达，通常不需要访问玩家的世界文件、启动游戏进程或连接在线服务。它们更接近可交互的工具，而不是百科文章或完整知识阅读体验。

ECL 已通过 ADR 0032 确立原生功能入口与可选 Additions 的交付模式。本 ADR 决定将一组面向 Minecraft 原版规则的轻量工具作为独立官方 Addition 提供，并为其定义可由维护者独立准备、校验和更新的版本化数据格式。

本决策尤其需要与此前的 Wiki / 知识库方向区分：ADR 0035 曾提出以离线知识包作为知识中心的主要交付方式，后由 ADR 0036 将主要知识访问方式调整为受限嵌入式浏览器。本 ADR 不恢复被取代的离线 Wiki 方案，也不改变 ADR 0036 的浏览器边界。

## 决策

### 1. 建立独立的 Vanilla Toolkit 官方 Addition

原版工具集以一个独立的官方 Addition 交付，建议稳定标识为 `ecl.vanilla-toolkit`。它不并入 ECL Core，也不要求每一种小工具都拆成独立 Addition。

该 Addition 内部由多个相对独立的工具模块组成。首批规划范围包括但不限于：

- **附魔模拟与计算**：附魔台候选结果、附魔兼容性、铁砧合并与经验成本等。
- **指令辅助**：按版本查询指令语法、参数提示、常见命令生成与语法差异展示。
- **矿石分布图谱**：按版本展示矿石生成高度、分布特征、推荐挖掘高度及已知群系影响。
- **原版注册表查询**：群系、生物、方块、物品、状态效果、附魔、维度等名称、别名与 Registry ID 查询。
- **配方与酿造查询**：原版合成、熔炼、酿造及其版本差异。
- **游戏机制计算器**：经验、伤害、时间、坐标、红石或其他可明确建模的原版机制计算。
- **生物与生成规则查询**：原版生物生成条件、掉落和相关机制。

上述清单是产品范围示例，不代表所有项目必须在首个版本实现。具体工具交互、公式和功能优先级由 Feature Spec 或 Roadmap 管理，不在本 ADR 中冻结。

每个工具模块应尽量独立启用、独立测试；某个工具的数据缺失或实现不可用，不应导致整个 Addition 或其他工具失效。

### 2. 工具以结构化操作为中心，不以文章阅读为中心

Vanilla Toolkit 的主要输出应是可直接使用的结果，例如：

- 根据目标 Minecraft 版本生成可用的指令语法或命令文本；
- 根据输入条件计算结果并展示计算依据；
- 以图表或结构化列表呈现矿石分布和规则；
- 返回可复制的名称、命名空间 ID、参数或配方；
- 对比两个版本之间的条目、字段或规则变化。

工具可以提供简短说明、术语解释、数据来源和规则备注，以帮助用户理解结果；但不得将长篇百科文章、教程集合或 Wiki 页面阅读器作为其主要产品模型。

工具不得把未经验证的推测包装成精确计算结果。无法确定版本、输入条件不足、数据缺失或规则尚未验证时，应明确标记限制，并在必要时拒绝给出确定结果。

### 3. 明确与 ADR 0035、ADR 0036 的区别，不恢复离线 Wiki

本 Addition 与此前 Wiki / 知识库方案的职责边界如下：

| 维度 | ADR 0035 原离线知识库方向 | ADR 0036 受限知识浏览器 | 本 ADR Vanilla Toolkit |
|---|---|---|---|
| 核心目标 | 本地收录并阅读知识内容 | 访问指定外部知识站点 | 在 ECL 内直接完成原版工具操作 |
| 主要载体 | 文章、条目、媒体和本地索引 | WebView 页面 | 结构化数据、规则与计算逻辑 |
| 用户行为 | 搜索、阅读、浏览、跳转 | 浏览允许站点 | 输入、查询、计算、模拟、生成、比较 |
| 数据形态 | 文本内容及关联知识 | 远程网页内容 | 按游戏版本组织的机器可读数据 |
| 网络依赖 | 安装知识包后可离线阅读 | 访问站点需要网络 | 核心工具在数据包安装后离线运行 |
| 主要范围 | 原版与模组知识 | 指定站点的 Minecraft 知识访问 | 仅 Minecraft 原版规则与注册表 |

ADR 0035 仍保持 Superseded 状态。本 ADR 不改变其状态，也不撤销 ADR 0036 的受限站点、导航控制、WebView 安全与不做代理/镜像/抓取等决策。

Vanilla Toolkit 不提供通用 Wiki、文章目录、文章阅读器、站点镜像、网页抓取器或模组百科。用户需要阅读 Minecraft Wiki 或其他资料站时，仍由 ADR 0036 所定义的知识浏览器负责；Vanilla Toolkit 只在有明确工具价值时提供结构化、可操作的结果。

工具中的简短规则说明不等于重新建立百科系统。若未来确实需要文章式知识中心，应另行评估其产品目标和架构，不得借本 Addition 绕过 ADR 0035 / 0036 的决策。

### 4. 以 Minecraft 版本作为所有数据和规则查询的显式维度

所有可能随 Minecraft 版本变化的条目、命令、规则、配方和计算逻辑，都必须关联明确的游戏版本或版本适用范围。

工具默认可以从当前实例上下文取得目标版本；没有实例上下文时，必须允许用户明确选择版本。用户也可以主动切换版本或比较多个版本。

版本适用性不得只依赖简单的“最小版本 / 最大版本”判断。数据格式应能表达：

- 首次引入版本；
- 移除版本；
- 适用版本范围或明确版本集合；
- 特定版本的字段或规则变化；
- 快照版本及必要的特殊版本标识；
- 数据或规则的验证状态。

对于跨版本语义发生变化的项目，应保留独立版本记录或明确的差异记录，不得把旧版本数据直接套用到新版本。版本无法精确匹配时，应说明回退策略；默认不得静默选择一个看似接近但未经验证的版本。

### 5. 数据与工具实现分离，数据由维护者独立准备

Vanilla Toolkit 的工具实现与 Minecraft 版本数据分离。Addition 消费符合公开 Schema 的数据，不将大规模版本数据硬编码在 UI 或业务逻辑中。

本项目维护者负责准备、维护和更新首批原版数据。ECL 负责提供稳定的数据目录约定、Schema、模板、校验工具或校验规则，以及数据加载接口；本 ADR 不要求 ECL 自行建设 Wiki 爬虫、自动采集平台或在线数据服务。

建议在公有仓库为该 Addition 保留专用模板目录：

`additions/vanilla-toolkit/data-template/`

该目录用于存放数据包 Manifest 示例、版本目录示例、各数据域 Schema 和最小样例。实际发布数据与模板应区分，避免把尚未校验的草稿当成正式数据发布。最终目录与文件命名可在实现时细化，但必须保持可发现、可版本控制和可独立校验。

数据包至少应声明：

- 数据包 ID、数据版本和 Schema 版本；
- 支持的 Minecraft 版本或版本集合；
- 所包含的数据域及其覆盖范围；
- 数据来源、来源版本或获取时间；
- 数据维护者与更新时间；
- 每个数据文件的路径、大小和 SHA-256；
- 数据质量或验证状态；
- 必要的许可与归属信息。

数据应按领域和版本组织，避免一个文件承载所有版本与所有工具数据。工具可以按需加载相关数据域；更新某个领域的数据不应要求重新下载或重建无关数据。

### 6. 图标与游戏资源必须从用户本地的匹配实例解析

Vanilla Toolkit 可以使用 Minecraft 原版图标和其他必要的视觉资源，但官方 Addition 与其官方数据包不得直接捆绑未经确认授权的 Mojang 游戏纹理、模型或其他游戏资产，也不得通过第三方 Wiki、镜像站或其他未确认授权的来源代为打包。

资源展示必须以用户本地已安装的 Minecraft 实例为前提，并遵循以下规则：

- 只有当用户本地存在与目标 Minecraft 版本精确匹配的已安装实例时，才允许为该版本解析和显示对应游戏资源。
- 若不存在匹配版本的已安装实例，工具仍可在数据条件满足时提供纯文本、计算或其他不依赖游戏图像的能力；但不得显示其他版本的图标、内置替代纹理或从网络临时获取的 Mojang 资源。相关图标位置应显示明确的不可用状态，并提示“没有可用的版本实例”，引导用户安装或选择对应版本的实例。
- 用户拥有多个匹配实例时，应允许用户选择资源来源实例；默认使用当前上下文实例。资源来源实例与工具查询所使用的数据版本必须一致，不得静默跨版本借用资源。
- 资源解析应尊重所选实例实际生效的资源包配置与优先级。资源包可以改变原版外观，因此不得假定所有实例都呈现相同的原版图标；需要提供清晰的资源来源说明。
- 对于资源包未覆盖的条目，可以按 Minecraft 的资源解析规则回退到该实例对应版本的原版资源；不得回退到其他 Minecraft 版本的素材。
- 资源只在本地读取、解析和缓存，不修改原始客户端文件，不上传至 ECL 服务或第三方服务，也不通过诊断日志泄露资源包或客户端内容。
- 本地缓存必须按 Minecraft 版本、资源来源实例/资源包状态及内容哈希进行隔离或校验，避免实例切换后继续显示旧资源。相同且经校验一致的资源可以去重存储，但不能因此混淆其来源和适用版本。
- 实例卸载、版本变更或资源包变更后，应使相关资源索引失效或重新验证；解析失败时显示通用占位状态，不得影响工具主体功能。

本决策限制的是 ECL 官方交付物和运行时资源来源，不构成对 Mojang 资产使用行为的法律许可或法律意见。仅从用户本地客户端读取资源可以避免 ECL 主动再分发这些资产，但不应据此宣称所有本地提取、缓存或展示行为必然获得授权。实现前仍需遵守适用的 Minecraft 使用条款和法律要求；不得将提取出的资源重新打包、导出或提供给其他用户。

### 7. 数据质量、来源与不确定性必须可追溯

原版数据也可能来自不同渠道，且不同来源对注册表、命令语法、世界生成机制和内部规则的覆盖程度不同。数据包必须记录可追溯的来源信息，并区分：

- 从目标版本游戏文件或官方发布数据中直接提取的事实；
- 从可检查的游戏代码或协议定义中推导的规则；
- 从官方文档或社区资料整理的说明；
- 通过测试或实机验证的行为；
- 尚未验证或仅供参考的信息。

数据来源公开可访问不自动代表允许复制、改编或再分发。数据维护者必须遵守来源许可证和使用条款；无法确认再分发权限的内容不得直接进入官方数据包。必要时应改为独立编写、仅保存允许使用的事实性结构，或保留来源链接。

对概率、随机过程、世界生成和其他复杂机制，必须说明计算模型、假设和适用条件。若结果是近似值、统计期望或经验建议，应明确标记，不得显示为游戏引擎保证产生的精确结果。

### 8. 本地优先、离线可用，不依赖在线服务

已安装且与目标版本匹配的数据应能在本地使用。查询、计算、模拟和版本比较不得要求连接 ECL 自有服务器或第三方 API。

网络仅用于用户主动安装或更新 Addition / 数据包等分发行为。网络不可用、目录服务不可用或更新失败时，已安装且校验通过的数据仍应可用。

工具不得上传玩家日志、存档、世界 Seed、服务器地址、账户信息或其他实例数据。若未来某项工具确实需要读取本地实例信息，应在本地完成，并遵循对应领域已有的隐私与文件访问边界。

### 9. 遵循 ADR 0032 的 Addition 生命周期和安全边界

Vanilla Toolkit 作为官方 Addition，遵循 ADR 0032 的目录、版本、依赖、签名、哈希、安装事务、兼容性检查和生命周期规则。

ECL 原生界面负责功能入口、未安装状态、安装提示和错误反馈；Addition 通过受控接口提供工具能力，不得动态注入任意 WPF 页面、导航项或脚本。

Addition 与数据包均按需加载。未安装、禁用、损坏或版本不兼容时，不得影响 ECL 普通启动、实例管理或 Minecraft 启动。数据包更新失败不得破坏当前可用数据版本。

### 10. 首期只针对 Minecraft 原版，不承诺模组规则兼容

首期数据与工具仅覆盖 Minecraft 原版。不得将模组注册表、模组指令、模组配方、模组生成规则或第三方 Loader 行为默认为本 Addition 的支持范围。

如果当前实例安装了模组，工具仍可在明确选择原版规则集时工作，但必须提示结果只代表原版，不代表该实例经过模组修改后的实际行为。

未来若需要模组支持，应设计独立的数据来源、命名空间、Loader 适配、冲突处理和兼容性模型；不能简单把模组数据混入原版数据集并声称完整支持。

### 11. 工具失败与数据缺失必须局部隔离

一个数据域缺失、文件损坏、Schema 不兼容或单个工具初始化失败，不得导致整个 ECL 或其他无关工具不可用。

加载数据前应执行 Schema、路径、大小、版本范围和完整性校验。校验失败的数据不得参与计算；界面应说明受影响的工具和数据域，并提供修复或重新安装入口。

数据更新应采用暂存与原子切换，更新中断或新数据校验失败时保留上一份可用数据。工具不得静默混用来自不同数据版本、不同 Schema 或不兼容 Minecraft 版本的数据文件。

## 备选方案

### 方案 A：将所有工具直接内置于 ECL Core

不采用。它会把可选数据和工具维护成本转嫁给所有用户，增加主程序体积和发布耦合，也会使数据修正必须等待启动器版本发布。此类工具并非普通游戏启动的必要条件。

### 方案 B：每个小工具独立建立一个 Addition

不采用。工具之间共享版本数据、查询基础设施和 UI 入口，拆成大量微型扩展会增加安装、依赖、版本兼容和维护负担。除非未来某个工具形成明显独立的大型能力，否则应保留在同一个 Vanilla Toolkit Addition 内。

### 方案 C：重新建立离线 Wiki 或知识文章库

不采用。该方向与 ADR 0035 已被取代的主要交付方式相同，也会重新引入内容授权、文章索引、媒体、更新和持续维护负担。用户需要网页知识访问时已有 ADR 0036；本 ADR 解决的是结构化工具操作，不是文章阅读。

### 方案 D：所有工具直接调用在线 Wiki 或第三方 API

不采用。它会让核心操作依赖网络、第三方服务可用性和远程数据格式，无法保证离线可用，也难以保证版本精确性。外部资料可以用于数据维护和来源核验，但运行时查询应优先使用本地版本数据。

### 方案 E：独立官方 Addition + 版本化本地数据

采用。它在普通用户启动成本、数据维护独立性、离线体验和功能演进之间取得平衡，并复用 ADR 0032 已确定的扩展分发体系。

## 后果

### 正面影响

- 玩家可以在 ECL 内完成高频、目标明确的原版查询和计算，减少切换网页与手工核对版本的成本。
- 工具逻辑与数据分离，维护者可以独立增加版本数据、修正规则和补充数据域。
- 一个 Addition 承载多个轻量工具，避免微型扩展过多。
- 当前实例版本可以成为默认查询上下文，减少版本误用。
- 本地数据支持离线查询，不依赖在线 Wiki 或 ECL 自有服务。
- 工具输出结构化、可复制、可比较，也能为未来其他 ECL 功能提供受控的数据接口。
- 与 ADR 0035 / 0036 的职责分离明确，不需要改变既有知识访问架构。

### 代价与风险

1. **版本数据维护量可能很大。** 从旧版到新版本的注册表、指令、配方和机制并非简单累加，需要持续维护版本边界和差异。
2. **不同工具对数据精度要求不同。** ID 查询相对直接，附魔随机模拟和世界生成计算则可能涉及复杂算法、随机种子和实现细节；不能把同一验证标准套用到所有工具。
3. **版本范围会扩大测试矩阵。** 需要对代表性旧版、关键规则变更版本、当前稳定版和快照版本建立测试样本。
4. **数据来源与许可仍需审查。** 原版事实数据、官方资源、社区整理数据和说明性文字可能具有不同的使用条件。
5. **数据模板和 Schema 需要长期兼容。** Schema 变更必须有版本号、迁移或拒绝策略，不能让旧数据被静默误读。
6. **工具界面可能不断膨胀。** 应优先保留短流程、高频、可明确验证的工具，避免把 Addition 变成第二个百科或杂乱的功能集合。
7. **“最优”结果依赖假设。** 例如最优挖矿高度、最优群系或最佳策略，必须说明目标函数、版本、条件和数据依据，不能将情境相关的建议表达为绝对结论。

## 实施顺序建议

1. 在 `additions/vanilla-toolkit/data-template/` 建立数据模板目录，先定义 Manifest、Schema 版本和最小样例。
2. 确定数据域的公共版本标识、版本适用范围、来源与验证状态表达方式。
3. 实现数据包解析、Schema 校验、完整性校验、版本选择和本地加载接口。
4. 选择结构简单且容易验证的 Registry ID 查询作为首个端到端工具。
5. 增加指令版本查询和配方查询，验证同一数据模型能否覆盖不同结构的数据域。
6. 再实现附魔模拟、矿石分布图谱和机制计算器；复杂模拟必须建立独立的参考测试与假设说明。
7. 实现当前实例版本联动、手动切换版本和跨版本差异比较。
8. 验证数据包独立更新、失败回滚、离线使用和单个数据域故障隔离。
9. 根据真实维护成本和用户使用情况决定是否扩大工具范围，不以工具数量作为完成标准。

## 验收标准

- Vanilla Toolkit 以独立官方 Addition 存在，不属于 ECL Core，且不是每个小工具各自一个 Addition。
- 未安装或禁用该 Addition 时，ECL 普通启动、实例管理和 Minecraft 启动不受影响。
- Addition 的功能入口与未安装状态遵循 ADR 0032，由 ECL 原生 UI 提供；扩展不得任意注入 UI。
- 公有仓库中存在明确、可发现的 `additions/vanilla-toolkit/data-template/` 模板目录，至少包含 Manifest 示例、Schema 版本说明和最小数据样例。
- 数据与工具实现分离；新增或修正版本数据不要求修改工具 UI 或将全部数据硬编码进程序。
- 每个数据包可识别自身版本、Schema 版本、Minecraft 适用版本、数据域、来源、更新时间和验证状态。
- 数据文件路径、大小、哈希和 Schema 在加载前完成校验；无效数据不得参与查询或计算。
- 工具能够默认使用当前实例的 Minecraft 版本，并允许用户手动选择其他版本。
- 版本不匹配、缺少数据或规则未经验证时，界面明确提示，不静默套用其他版本数据。
- 图标和游戏资源仅从用户本地精确匹配的已安装实例解析；没有对应版本实例时显示“没有可用的版本实例”，不从官方 Addition 或网络补充未经确认授权的游戏资产。
- 资源解析尊重所选实例的资源包配置；资源包变更或实例切换后不会错误复用旧资源。
- 至少一个 Registry 查询工具能在断网状态下使用本地数据完成查询，并返回可复制的名称和 ID。
- 数据包更新失败或中断不会破坏上一份可用数据；单个数据域损坏不会导致其他工具或 ECL 主程序不可用。
- 工具结果能够区分精确数据、近似计算、经验建议和未经验证的信息，并说明必要的适用条件。
- 首期明确只支持 Minecraft 原版；模组或 Loader 修改后的行为不会被误报为原版工具已覆盖。
- 本 Addition 不提供 Wiki 文章阅读器、全站镜像、爬虫或在线知识代理，不改变 ADR 0035 / 0036 的状态与边界。
- 工具运行时不要求连接 ECL 自有服务器或第三方 API，不上传玩家日志、世界 Seed、存档或账户信息。
