# ADR 0014：Java 运行时优先级与兼容性策略

- Status: Completed
- Date: 2026-11-01
- Scope: Java 发现、验证、兼容性评估、启动计划、WPF 与 CLI

## 背景

旧版 Java 策略将实例路径、全局路径、自动选择和最高版本兜底组合成固定优先级，并允许关闭兼容性检查。这种方式无法表达多个 Java 安装之间的用户偏好，也可能让一个排在前面的不兼容运行时被错误选中。

Minecraft、Mod Loader 以及整合包中的 Mod 都可能影响 Java 需求。单纯根据 Minecraft 版本推断最低 Java 版本并不足够；同时，显式实例覆盖又是高级用户有意选择的行为，不应被自动选择逻辑悄悄覆盖。

## 决策

### 1. 全局 Java 设置是有序优先级列表

- 用户可以登记多个 Java 安装并调整顺序。
- 自动选择按列表顺序遍历，选择第一个满足当前实例有效要求的可用运行时。
- 优先级只表达偏好，不代表兼容性豁免。
- 不兼容的候选必须跳过，不能因为它排在首位而被选中。
- 未配置列表时，可使用有界发现结果作为默认候选顺序；不得为此在启动时执行全盘扫描。

### 2. 按实例计算有效 Java 要求

有效要求需要综合以下来源：

1. Minecraft 版本元数据，优先使用版本 JSON 中明确声明的 Java 要求。
2. Mod Loader 的运行时要求。
3. Mod 的 Java 要求，但仅在存在可信证据时纳入。
4. 实例自身明确声明的约束。

每项要求应保留来源、约束内容与证据质量。可信项目元数据和 Loader 兼容信息可作为强证据；字节码 class-file 版本可提供最低版本线索，但不能证明完整运行时兼容性；文件名、任意文本和未经核实的社区说法不得直接成为硬约束。

硬约束冲突时应返回可解释的冲突结果，不得简单选择最高版本掩盖冲突。未知要求不等于不兼容。

### 3. 实例级 Java 覆盖是显式固定

- 用户为实例指定 Java 后，ECL 不得在后台静默替换该路径。
- 启动前仍必须评估兼容性。
- 若检测到不兼容，向用户解释具体风险；用户明确接受后，允许继续使用该覆盖运行时。
- 风险接受记录绑定稳定风险身份：规范化 Java 可执行文件路径、检测到的 Java 版本和当前有效要求。
- 上述身份发生实质变化时，之前的接受记录失效并重新提示。
- 风险接受只代表用户对该实例固定运行时的显式例外，不会关闭兼容性检测，也不会影响自动选择。

### 4. 32 位 Java 一律拒绝

Minecraft 启动不接受 32 位 Java。必须检测并明确说明拒绝原因，不得仅隐藏候选或将其当作普通兼容性警告。

### 5. 发现、验证与列表管理

- Java 发现应有界、可取消、去重，并能容忍单个候选损坏或不可访问。
- 不在 ECL 启动时执行无边界全盘扫描。
- 验证进程应有超时；扫描过程不能被一个卡死或格式异常的 Java 阻断。
- 支持 PATH、JAVA_HOME、常见安装目录、注册表、Minecraft 自带运行时及用户导入路径等来源。
- 从 ECL 列表移除某项只解除注册，不删除 Java 文件。卸载 ECL 管理的运行时必须是独立且明确的操作。

### 6. Core 统一决策语义

Java 发现、要求聚合、兼容性判断和最终选择属于 Core 领域能力。WPF 与 CLI 必须调用相同服务，不得分别实现不同的选择规则。

启动计划应记录最终 Java 路径、版本、架构、有效要求摘要、选择原因及被拒候选的原因，以支持诊断和复现。

## 后果

### 正面

- 用户可以为不同实例安装并维护不同 Java，而无需反复修改单一路径。
- 自动选择尊重用户偏好，同时不会牺牲已知兼容性。
- 高级用户仍能显式固定特殊运行时，但必须理解并接受对应风险。
- Java 选择结果可以解释、审计并纳入诊断信息。

### 代价与约束

- 需要结构化的 Java 安装信息、要求模型、证据来源和选择结果。
- Mod 要求的可靠性参差不齐，不能把弱证据误当成硬约束。
- 发现与验证需要缓存、取消、超时和并发控制。
- 旧配置中的“关闭兼容性检查”不能再作为自动选择的绕过开关；兼容迁移不得恢复旧的全局豁免语义。

## 验收标准

1. 自动选择按优先级选择第一个兼容运行时，并跳过不兼容候选。
2. 实例级覆盖不会被静默替换；不兼容时必须先明确告知并获得用户接受。
3. Java 路径、版本或有效要求变化后，旧风险接受记录不再适用。
4. 32 位 Java 始终被拒绝。
5. WPF 与 CLI 对同一实例给出一致的 Java 选择结果。
6. 单个损坏或卡死的候选不会阻断整个发现过程。
