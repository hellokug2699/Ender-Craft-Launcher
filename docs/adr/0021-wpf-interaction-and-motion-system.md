# ADR 0021：WPF 交互反馈与轻量动效系统

- Status: Proposed
- Date: 2026-11-02
- Scope: ECL.App 的 WPF 控件、主题资源、页面导航、弹窗与交互状态表现

## 背景

ECL.App 当前基于 WPF（`net10.0-windows`、`UseWPF=true`），采用 XAML、ResourceDictionary 与 MVVM。应用已经具备统一主题资源、品牌色、HarmonyOS Sans SC 字体、按钮模板和部分交互触发器，因此问题并不是缺少 UI 技术能力，也不应直接归因于 C# 本身。

当前体验仍存在明显短板：

1. 多数控件状态通过 Trigger 直接替换颜色或属性，缺少连续过渡；按下按钮时视觉差异弱，用户难以确认输入是否被接收。
2. 普通按钮、主按钮、Ghost 按钮和危险按钮分别维护模板，状态行为容易产生差异或遗漏。
3. 部分模板的焦点反馈实现不完整。例如主按钮模板中的 Border 未建立边框属性，却在键盘焦点触发器中尝试修改边框，导致焦点提示可能不可见。
4. 页面内容通过 ContentControl 切换，缺少统一的页面进入/离开表现；弹窗、展开区域、任务状态等也缺少一致的运动规范。
5. 现有主题主要定义静态颜色和控件样式，尚未形成可复用的动效令牌、减少动态效果策略和性能约束。
6. 如果逐页、逐控件临时添加 Storyboard，短期可能改善观感，但会造成动画时长、缓动、状态优先级和可访问性策略碎片化。

WPF 已提供 ControlTemplate、VisualState/Trigger、Storyboard、动画时钟、RenderTransform、Opacity 等能力。现阶段没有证据表明 ECL 需要替换 UI 框架或引入独立渲染引擎。

## 决策

### 1. 保留 WPF 与现有应用架构

- 继续使用 WPF、XAML、现有 MVVM 和 ResourceDictionary。
- 不因补充动效而迁移到 WinUI 3、Avalonia、WebView 或游戏引擎式渲染框架。
- 不把业务状态、命令执行或后台任务生命周期绑定到动画完成事件。
- 动效属于表现层能力；动画中断、窗口失焦或减少动画偏好不得改变业务结果。

### 2. 建立集中式交互与动效设计系统

在 ECL.App 的主题资源中建立统一的设计令牌与样式约定，至少覆盖：

- 颜色状态：Normal、Hover、Pressed、Focused、Selected、Disabled、Loading，以及 Success、Warning、Danger 等语义状态。
- 动效时长：Instant、Fast、Normal、Slow 等有限档位，具体毫秒值由实现阶段统一确定并通过实机观感校准。
- 缓动曲线：进入、退出、强调反馈采用有明确语义的缓动配置，避免各页面任意选择曲线。
- 位移与缩放：优先使用小幅 RenderTransform，不通过反复改变布局尺寸制造反馈。
- 焦点环、边框、圆角、阴影和间距继续由共享资源统一管理。

资源键应具有明确命名规则，避免将某个控件专属资源误当成全局令牌。控件模板可以有差异，但相同交互状态必须具有一致的语义和可感知程度。

### 3. 统一按钮及可交互控件状态

所有按钮变体应遵循同一状态模型，并允许主操作、次操作、Ghost 和危险操作保留各自语义配色。

- Hover：提供清晰但克制的背景、边框或亮度变化。
- Pressed：提供即时、明确的按下反馈；允许轻微缩放或位移，但不得造成明显布局抖动。
- Released：平滑回到 Normal 或 Hover 状态。
- Focused：键盘导航时显示真实可见的焦点指示，不得只依赖鼠标悬停样式。
- Disabled：明确不可操作，且不显示误导性的 Hover/Pressed 状态。
- Loading：需要异步执行的操作可显示忙碌反馈，并防止重复提交；具体禁用策略由对应命令决定。
- Selected：导航项、页签和过滤器等持续选中状态应与短暂 Hover/Pressed 区分。

实现必须检查模板中实际参与绘制的元素及其 BorderBrush、BorderThickness、Opacity 等属性，避免触发器修改了未配置或不可见的属性。鼠标、键盘、触摸/笔输入（若适用）应尽可能保持一致。

### 4. 定义克制、可预测的动效范围

首批统一覆盖以下场景：

| 场景 | 允许的反馈 | 约束 |
|---|---|---|
| 按钮按下/释放 | 颜色过渡、轻微缩放 | 必须即时响应，不等待动画结束才执行命令 |
| 卡片与列表项悬停 | 背景、边框或轻微位移 | 不改变布局，不制造大面积跳动 |
| 页面切换 | 短暂淡入，必要时辅以极小位移 | 导航与数据上下文切换仍由 ViewModel 控制 |
| 对话框/弹窗 | 淡入与轻微缩放 | 关闭、取消和系统窗口行为不能被动画阻塞 |
| Expander | 内容展开/收起与指示符旋转 | 内容测量和滚动行为必须稳定 |
| 任务进度 | 进度值平滑变化，状态变化有明确提示 | 不以动画帧率作为进度数据来源 |
| 加载状态 | 轻量忙碌指示 | 不为静态页面制造无意义的持续动画 |

避免装饰性粒子、持续漂浮、视差、大范围弹跳和长时间转场。启动器的主要工作是管理实例、下载和启动游戏，动画不能降低操作效率或遮挡状态信息。

### 5. 页面导航动画必须与视图生命周期解耦

- 页面切换动画只负责呈现，不负责创建、销毁或保存页面状态。
- 动画取消或被系统禁用时，页面必须立即进入正确的最终视觉状态。
- 不得为动画而重复创建 ViewModel、重复触发数据加载或重新执行导航命令。
- 页面切换期间应避免旧页面继续接收不应处理的输入。
- 若采用 ContentControl 转场容器，应确保只存在一个明确的当前页面状态，并避免为简单淡入引入复杂的双树缓存机制。

### 6. 尊重减少动态效果与可访问性

- 提供统一的减少动效策略，并在 Windows 用户偏好明确要求减少动画时禁用或缩短非必要运动。
- 即使动效关闭，Hover、Pressed、Focused、Selected、Disabled 等状态仍必须通过颜色、边框、图标或其他静态变化清晰表达。
- 不以颜色作为唯一状态信号；重要状态应结合文本、图标或形状。
- 保留键盘 Tab 导航、可见焦点、快捷键、AutomationProperties 和合理的控件语义。
- 不闪烁、不快速重复缩放，不使用可能诱发不适的高频或大幅运动。

### 7. 动画必须满足性能与线程边界

- 不在 UI 线程执行下载、文件 IO、哈希计算、进程管理或日志处理。
- 动画使用 WPF 原生动画能力，优先动画化 Opacity 与 RenderTransform 等适合合成的属性；避免高频动画布局属性。
- 不在每帧回调中分配对象、更新业务数据或触发 ViewModel 命令。
- 动画资源应可复用，页面离开、控件卸载或窗口关闭时应停止不再需要的时钟与订阅。
- 不引入常驻高频 DispatcherTimer 作为通用动画引擎。
- 在低性能设备、窗口遮挡、快速连续导航和大量任务卡片场景下验证 UI 响应性。
- 动效不得影响游戏进程、LogHost、下载服务和诊断会话的存活及连续性。

### 8. 渐进式落地，不进行一次性全量重写

实施顺序建议如下：

1. **基线修复**：审查共享按钮模板和焦点状态，修复不可见边框、状态优先级和禁用态问题。
2. **基础动效令牌**：建立统一时长、缓动和减少动效策略。
3. **核心控件**：先覆盖 Button、导航项、页签、列表项、Expander 和弹窗。
4. **页面转场**：在不改变导航和 ViewModel 生命周期的前提下，为主内容区域增加轻量转场。
5. **任务反馈**：优化下载、安装和启动相关的进度、忙碌、成功与失败状态呈现。
6. **逐页迁移与清理**：按页面替换局部重复样式，删除已失效或互相冲突的模板规则。

每一阶段均应可独立合并、回归和回滚，不要求一次性重写所有页面。

### 9. 不默认引入第三方 UI 或动画依赖

优先使用 WPF 原生能力。只有在明确存在原生能力无法合理解决的需求、评估维护成本与许可证，并通过独立决策后，才考虑第三方控件库或动画库。

## 后果

### 正面影响

- 按钮和控件能明确表达输入已被接收，减少“点击了但没反应”的不确定感。
- 页面、弹窗、列表和任务中心形成一致的运动语言，改善整体完成度。
- 继续复用现有 WPF、MVVM 和主题体系，不引入框架迁移成本。
- 集中管理动效和交互状态，降低后续页面开发时的样式分叉。
- 减少动态效果和键盘焦点行为成为系统级设计约束，而非事后补丁。

### 成本与风险

- 自定义 ControlTemplate 和 Storyboard 会增加 XAML 复杂度，需要严格控制资源命名和状态优先级。
- 动画时钟、模板重用和控件卸载处理不当可能造成额外资源占用。
- 过度动画会降低高频操作效率，甚至影响低性能设备上的流畅度。
- 现有页面可能存在局部样式覆盖，迁移时需要逐页检查，不能只修改共享主题就假定全站一致。
- Windows 减少动画偏好、键盘焦点和高 DPI 等场景需要额外验证。

## 验收标准

1. ECL.App 不引入新的 UI 框架或必需的第三方动画依赖。
2. 共享按钮变体具有一致且可观察的 Hover、Pressed、Focused、Disabled 状态；主按钮焦点边框实际可见。
3. 鼠标点击后命令立即执行，不依赖动画完成；连续点击不会因动画产生重复业务操作。
4. 页面切换、弹窗和 Expander 在正常模式下具有统一、克制的过渡；快速连续操作时不会卡在中间状态。
5. 禁用动效或启用 Windows 减少动画偏好时，所有重要交互状态仍可辨认，页面立即到达正确最终状态。
6. 键盘用户能够识别当前焦点、完成导航并触发操作；重要状态不只通过颜色表达。
7. 动画不执行 IO、哈希、进程操作或日志处理，不阻塞业务任务，不依赖 UI 动画维持后台工作。
8. 在低性能设备、窗口遮挡、快速导航、大量任务项和窗口关闭等场景下无明显卡顿、残留动画或持续资源增长。
9. 页面转场不会重复创建 ViewModel、重复触发加载或改变原有导航语义。
10. 完成共享控件与核心页面迁移后，逐项记录人工验收结果；未迁移页面不得宣称已符合本 ADR。
