# ADR 0023：多实例来源目录登记与统一扫描

> 生命周期迁移说明：本次仅拆分决策与实施状态，不改变既有技术决策；尚未开始实施的提案保持原有阶段。

- Decision: Proposed
- Implementation: In Progress
- Date: 2026-11-02
- Scope: Minecraft 工作区、外部实例来源目录登记、实例扫描、实例展示与来源分组

## 背景

当前实例扫描逻辑难以覆盖用户在不同启动器或不同磁盘中维护的多个 Minecraft 实例目录。用户可能同时使用 HMCL、PCL 或其他启动器，并将各自的实例保存在不同位置，例如 D:/HMCL/.minecraft 与 D:/PCL/.minecraft。

如果 ECL 只扫描一个固定目录，用户就必须迁移实例或手动重复登记，破坏现有目录布局，也无法完整呈现 Minecraft 的磁盘占用。同时，多个来源目录可能包含名称相同的实例，目录结构也可能不同。仅使用实例名称或版本号作为唯一标识，会造成冲突、误操作和清理范围混淆。

## 决策

ECL 将实例发现模型扩展为：一个工作区登记多个实例来源根目录。每个来源目录独立登记、扫描和管理，扫描结果在 ECL 工作区中统一展示，但默认不复制或移动外部实例。

### 1. 支持登记多个实例来源根目录

用户可以在工作区设置或实例管理界面中添加多个包含 Minecraft 实例的目录，例如：

- D:/HMCL/.minecraft
- D:/PCL/.minecraft

目录由用户明确选择，ECL 不应根据目录名推断它必然属于 HMCL、PCL 或其他特定启动器。

每个来源记录至少包括稳定的来源 ID、用户选择的根目录规范路径、用户可编辑的显示名称、来源类型或结构识别结果（若可可靠识别）、最近扫描时间与扫描状态、是否启用自动扫描，以及目录可访问性和权限状态。

来源显示名称仅用于 UI，不作为路径身份或删除授权。

### 2. 来源目录与 ECL 工作区是不同概念

ECL 工作区是实例的统一管理与展示空间；实例来源根目录是实际文件所在位置。添加外部来源只登记路径并扫描，不意味着复制、移动、接管或重新初始化该目录。

移除来源登记默认只停止扫描并从 ECL 展示中移除，不删除来源目录及其中任何文件。若来源中仍有正在运行的实例，应提示用户并阻止产生悬空会话引用。

### 3. 实例扫描应以来源为边界

扫描器逐个扫描已登记来源，不应无边界地递归扫描整个磁盘。每种支持的目录结构应有明确的识别器和扫描深度或范围。

至少应支持识别常见 Minecraft 实例结构，并允许后续扩展其他启动器布局。无法识别的目录应报告为未识别内容，不得自动当作实例导入或清理。

扫描应支持单来源隔离失败、手动刷新和可配置自动扫描、取消操作、状态与最后成功时间展示；访问拒绝、磁盘离线、路径不存在等状态应可恢复。扫描只读取元数据，不修改实例内容。

### 4. 实例身份不能只依赖名称或版本号

实例的稳定身份应由来源身份与规范化实例路径共同确定，或使用等价的稳定身份方案。显示名称、Minecraft 版本号和文件夹名都不是唯一键。

同一物理实例被多个来源路径重复指向时，应检测并避免重复登记或重复计数；路径大小写、尾部分隔符、符号链接和目录别名需要进行一致性处理。不能可靠判断两个路径是否指向同一实体时，应标记潜在重复并交由用户确认。

同名但位于不同来源目录的实例应视为不同实例，不得覆盖彼此的元数据、启动配置或删除目标。

### 5. 工作区按来源分组展示实例

ECL 工作区中的实例列表应先按来源目录分组，再显示来源下的实例。例如：

- HMCL
  - 1.20.1
  - 1.21.1
- PCL
  - 1.12.2

来源分组应支持折叠和展开。每组可以显示来源名称、目录位置、实例数量、总占用空间和扫描状态；实例项显示名称、Minecraft 版本及必要的状态信息。

折叠仅影响展示，不应改变实例选择、运行状态、扫描状态或清理目标。

### 6. 来源与空间统计、清理功能共享同一模型

ADR 0022 的 Minecraft 空间统计和实例清理列表必须复用本 ADR 的来源 ID、实例身份与分组关系。

来源总占用由该来源下的实例占用及可识别的来源级共享数据构成；实例占用按明确的目录归属规则计算；共享缓存、公共库和无法归属的内容应单独展示，避免重复计数。清理某个实例时必须解析到唯一的来源和规范路径；同名实例不得导致清理目标歧义。

### 7. 外部实例默认只登记，不复制、不移动

添加来源目录时，ECL 不得自动复制、移动、重命名或清理其中的文件。ECL 不得为了统一目录结构而改写其他启动器的数据布局。

如果未来提供迁移功能，必须由用户主动发起，提供容量检查、完整性校验、冲突处理、失败恢复和源目录保留策略，并遵循工作区迁移相关架构决策。

### 8. 来源变更和失效处理

当来源路径被移动、删除、磁盘离线或权限变化时，保留来源登记信息和最后一次扫描结果，明确显示来源不可访问或需要重新定位；不得把暂时不可访问解释为实例已删除；不得因扫描失败自动清除实例元数据。用户重新定位来源时，必须重新验证路径和实例身份。

用户主动移除来源登记时，应提示这只会解除 ECL 的登记关系，不会删除磁盘文件。移除含活动实例的来源前必须处理活动会话引用。

### 9. 与现有工作区和安装边界兼容

本 ADR 不改变 ECL 程序安装目录、ECL 自身配置目录、Java Runtime 目录和 Minecraft 工作区之间的边界。

多来源登记是工作区实例发现能力的扩展，不代表允许安装器、更新器或卸载器擅自访问或清理所有登记目录。所有外部目录操作仍需遵循各自数据所有权和安全边界。

## 后果

正面影响：用户可以在 ECL 中统一查看多个启动器目录中的实例；无需迁移 HMCL、PCL 等已有实例即可纳入工作区；实例展示、空间统计和清理共享一致的来源分组；同名实例不会因名称冲突而互相覆盖；来源失效不会被误判为实例删除。

代价：需要维护来源登记、扫描器、实例身份和重复路径检测；不同启动器的目录布局需要独立识别器和测试；多来源扫描增加磁盘 IO，需要限流、取消和状态管理；清理和删除必须严格使用来源与实例的稳定身份，不能仅凭 UI 名称执行。

## 验收标准

1. 用户可以在同一个工作区登记至少两个不同的实例来源目录。
2. D:/HMCL/.minecraft 与 D:/PCL/.minecraft 这类目录可以分别扫描并在 ECL 工作区展示。
3. 工作区实例列表按来源分组，来源组支持折叠和展开。
4. 来源组展示名称、路径、实例数量、总占用和扫描状态；实例项展示实例名称与版本信息。
5. 添加来源只登记和读取目录，不复制、移动、重命名或修改其中的实例。
6. 同名但路径不同的实例可以并存，且启动、统计、清理和删除目标不会混淆。
7. 单个来源不可访问或扫描失败时，其他来源仍可正常展示和扫描。
8. 扫描可取消、可刷新，且不会阻塞 UI 或修改实例文件。
9. 暂时离线、权限不足或路径不存在不会导致来源及实例登记被自动删除。
10. 移除来源登记不会删除来源目录或实例文件，并明确告知用户这一点。
11. 对重复指向同一物理目录的来源能够检测、避免重复统计，或明确标记待用户处理。
12. ADR 0022 的空间统计和清理列表能够使用相同来源分组与实例身份，且不存在同名实例误删。
13. 对未知目录结构采取保守策略，不自动导入为实例，也不对其执行清理。
14. 多来源扫描有明确的 IO 并发限制、错误报告和恢复行为。
