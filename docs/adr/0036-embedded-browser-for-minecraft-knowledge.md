# ADR 0036: Embedded Browser for Minecraft Knowledge Access

- Decision: Proposed
- Implementation: Not Started
- Date: 2026-11-02
- Scope: ECL 内置 Minecraft 知识浏览器、允许访问的站点范围、导航控制与浏览器安全边界
- Related: [ADR 0032：原生功能入口与按需 Additions 扩展体系](0032-native-feature-interfaces-and-optional-additions.md)、[ADR 0033：本地 Minecraft 全面诊断与知识引擎](0033-local-minecraft-diagnostic-and-knowledge-engine.md)、[ADR 0035：可选离线 Minecraft 知识库](0035-offline-minecraft-knowledge-library.md)

## 背景

ECL 希望为 Minecraft 玩家提供一个原生知识入口。此前考虑通过内置浏览器直接访问第三方资料站，以减少全量离线知识库的内容授权、同步、包体积和维护负担。

进一步明确产品边界后，ECL 不需要提供通用网页浏览器，也不希望用户通过这个入口访问任意互联网内容。内置浏览器的职责应收敛为访问两个明确指定的 Minecraft 知识来源：

- minecraft.wiki 的中文站点 zh.minecraft.wiki；
- mcmod.cn。

为兼容这些站点自身合理使用的子域名，允许上述两个域名树下的所有子域名，但不允许其他注册域名、相似域名或任意外部站点。浏览器的地址栏用于展示当前地址和复制地址，不提供手动编辑或任意导航能力。

因此，本 ADR 将内置浏览器重新定义为**受限知识浏览器（Restricted Knowledge Browser）**。站点白名单必须是底层导航和网络请求的安全边界，而不是仅在 UI 上隐藏地址输入框。

## 决策

### 1. 浏览器只允许两个指定域名树

允许的主机名范围为：

- zh.minecraft.wiki 及其所有子域名；
- mcmod.cn 及其所有子域名。

主机名匹配必须基于 URL 解析后的规范化 hostname，并采用 DNS 标签边界判断。逻辑等价于：

- hostname 等于 zh.minecraft.wiki，或以 .zh.minecraft.wiki 结尾；
- hostname 等于 mcmod.cn，或以 .mcmod.cn 结尾。

不得使用简单的字符串包含判断。大小写、国际化域名和尾随点等输入应先按一致的 URL/主机名规范化规则处理，再进行白名单判定。用户信息段、端口和路径均不能改变 hostname 的归属判断。

例如：

- zh.minecraft.wiki：允许；
- static.zh.minecraft.wiki：允许；
- mcmod.cn：允许；
- api.mcmod.cn：允许；
- zh.minecraft.wiki.example.com：拒绝；
- evil-zh.minecraft.wiki：拒绝；
- mcmod.cn.example.org：拒绝；
- zh.minecraft.wiki@evil.example：拒绝。

仅允许 HTTPS。HTTP、file:、data:、javascript:、ftp:、自定义协议及其他非 HTTPS 导航均拒绝，不自动升级后放行。若未来确实需要新增来源，必须通过 ADR 修订明确审核并加入白名单，不得运行时自动信任页面提供的域名。

### 2. 地址栏只读，只提供复制

地址栏是当前页面地址的展示控件，不是浏览器导航输入框。

- 显示当前页面 URL；必要时可在视觉上截断，但复制操作必须取得完整 URL。
- 用户可以选中或通过专用复制操作复制完整地址。
- 不允许编辑、输入、粘贴、搜索或按 Enter 导航。
- 不提供“在系统浏览器打开任意地址”的通用入口。
- 页面导航仅由当前允许站点内的链接、浏览器自身的后退/前进/刷新等受控操作触发。
- 地址栏不得接受拖放 URL、剪贴板粘贴或其他绕过只读交互的输入。

浏览器不提供通用搜索框。站内搜索可以使用允许站点自身页面中的搜索功能，但其提交请求仍受同一白名单策略约束。

### 3. 站内导航允许跨两个白名单域名树

只要导航目标通过白名单和 HTTPS 校验，就允许站内跳转，包括：

- zh.minecraft.wiki 页面跳转到其子域名；
- mcmod.cn 页面跳转到其子域名；
- 两个允许域名树之间互相跳转。

这里的“站内”是指目标仍属于上述两个允许域名树之一，而不是必须与当前页面保持相同 hostname。导航目标必须在实际提交或跟随之前完成校验。

所有顶层导航入口均须执行同一策略，包括普通链接、脚本触发的导航、表单提交、刷新、历史记录恢复、弹窗和新窗口请求。新窗口请求不得创建不受控的第二个 WebView；若目标通过白名单检查，应在当前受控浏览器上下文中打开，否则拒绝。

### 4. 外部导航必须由 ECL 拦截并显示自有错误页面

任何顶层导航目标不属于允许域名树，或使用非 HTTPS 协议时，ECL 必须拒绝连接并显示由 ECL 本地提供的错误页面。

错误页面至少应包含：

- 错误类型：目标站点不在允许范围内，或协议不受支持；
- 原始请求地址；
- 被拒绝的目标地址（如果存在）；
- 明确的“连接已被 ECL 拒绝”提示。

错误页面必须由 ECL 本地生成，不得从被拦截的网站加载资源，也不得自动打开系统浏览器。展示 URL 时应进行安全编码和长度限制，避免错误页面自身受到注入影响。

### 5. 重定向必须逐跳检查，外部目标不得跟随

HTTP 3xx 重定向属于导航安全边界的一部分。ECL 不得依赖最终页面加载完成后的 URL 检查，因为此时外部目标可能已经被请求。

对于每一条重定向响应：

1. 在跟随该响应的 Location 之前取得状态码和目标地址；
2. 解析并规范化目标 URL；
3. 目标属于允许域名树且协议为 HTTPS 时，才允许继续；
4. 目标不符合白名单时，必须阻止跟随，并显示 ECL 自有错误页面；
5. 错误页面应直接展示原始 3xx 状态码（例如 HTTP 301、302、303、307 或 308）、原始请求地址和被拒绝的重定向目标。

重定向到另一个允许域名树的情况可以继续，但每一跳都必须重新校验；连续重定向不得绕过检查。相对 Location 必须相对于当前响应 URL 正确解析后再检查。缺失、格式错误或无法安全解析的 Location 一律拒绝。

实现时必须验证所选 WebView 运行时能否在请求被跟随前可靠地检查并阻止重定向。若仅靠导航事件无法取得原始 3xx 状态码或无法保证在跟随前取消，则必须增加能够在网络响应层拦截重定向的宿主机制；不得退化为“先访问外部目标，再检查最终地址”。若运行时无法提供该保证，应视为实现阻塞项。

对由重定向触发的拒绝，不得只显示笼统的“无法访问网页”或网络错误，必须保留并显示实际 3xx 状态码。

### 6. 子资源也受同一允许域名树约束

为贯彻“浏览器只能加载这两个站点下的内容”，页面发起的网络请求默认也必须限制在上述两个允许域名树及 HTTPS 范围内，包括图片、脚本、样式表、字体、XHR/fetch、媒体、iframe 和其他网络子资源。

不得因为某个页面引用了 CDN、统计服务、广告域名或第三方图片站，就自动放宽白名单。若严格策略导致站点部分内容无法显示，应接受该内容不可用，并在必要时提供说明；新增域名必须经过明确审核并修订本 ADR，不能通过通配外部域名解决兼容问题。

iframe 不得加载白名单以外的来源。允许域名内的 iframe 仍受 WebView 沙箱和导航策略约束，不得获得 ECL 宿主对象或本地文件能力。

### 7. 弹窗、下载和外部协议默认拒绝

- 弹窗默认禁止；站内新窗口链接经过白名单校验后可在当前受控浏览器中打开。
- 下载默认禁止，不启动外部下载器，也不静默写入本地文件。
- 外部协议调用一律拒绝，不交由系统处理。
- 网页不得通过剪贴板写入、拖放、文件选择器或其他能力绕过地址栏只读和站点限制。
- 摄像头、麦克风、地理位置、通知等权限默认拒绝。
- 不向网页暴露任意 ECL/.NET bridge、本地文件系统、启动游戏、修改实例或管理配置的能力。
- 开发者工具不向普通用户开放。

未来如确有下载或其他特殊能力需求，应单独定义来源校验、用户确认、文件安全和数据生命周期，不得默认开放。

### 8. 浏览器来源和产品身份必须明确

浏览器界面应明确标识这是 ECL 的受限 Minecraft 知识浏览器，并显示当前页面地址。用户应能区分网页原始内容与 ECL 自己提供的导航控件、错误提示和帮助信息。

ECL 不得将第三方页面包装成 ECL 官方撰写或审核的内容。页面本身的准确性、版本适用性和维护状态由原始站点负责；ECL 不因允许访问而对其内容作背书。

### 9. 保留 WebView 沙箱，不向网页开放本地能力

内置浏览器应使用成熟 WebView 运行时的安全机制，不得为适配页面而关闭同源策略、沙箱或其他关键安全功能。

若采用 WebView2，应明确 Evergreen Runtime 或固定版本 Runtime 的部署策略、最低版本、更新策略和缺失时提示。浏览器用户数据目录、Cookie、缓存和会话数据应独立于 ECL 主程序及系统浏览器，并有明确生命周期。

浏览器运行时缺失、初始化失败、页面崩溃、网络不可用或白名单拦截，不得阻塞 ECL 启动、实例管理或 Minecraft 启动。

### 10. 不建立内容代理或镜像服务

浏览器直接通过用户设备访问允许的原始站点。ECL 不建立服务器端网页代理、内容镜像或第三方资料抓取服务，也不绕过站点登录、付费墙、访问控制、反自动化措施或其他服务条款。

本 ADR 的严格站点限制不是授权 ECL 抓取或再分发站点内容。小型、明确授权的 ECL 自有离线帮助资料仍可作为补充，但不属于内置浏览器白名单内容。

## 备选方案

### 方案 A：通用内置浏览器，允许任意 URL

不采用。它会把知识入口扩展成通用浏览器，扩大攻击面和产品维护范围，也与 ECL 希望提供专注、受控知识访问的定位不符。

### 方案 B：只限制顶层页面，不限制子资源

不采用。外部 iframe、脚本、图片或其他子资源仍可能引入白名单之外的网络内容，使“只能访问指定站点”的边界变得不完整。

### 方案 C：仅在导航完成后检查最终 URL

不采用。外部重定向目标可能已经被请求，无法满足在连接前拒绝的要求，也可能丢失原始 3xx 状态和目标信息。

### 方案 D：两个指定域名树的受限浏览器

采用。允许 zh.minecraft.wiki、mcmod.cn 及其子域名，地址栏只读，站内导航可用，外部导航和外部重定向在连接前拒绝，并由 ECL 显示自有错误页面。其代价是部分站点功能可能因依赖外部 CDN 或第三方资源而无法完整显示。

## 后果

### 正面影响

- 浏览器的产品职责清晰，不会演变成通用浏览器。
- 用户无法通过地址栏输入任意 URL，普通交互路径受到明确约束。
- 顶层导航、重定向和子资源都具有统一的域名边界。
- 外部重定向在跟随前被拒绝，并保留实际 3xx 状态供用户理解。
- ECL 不需要运营网页代理、镜像或内容同步服务。
- WebView 网页内容无法直接获得 ECL 本地管理能力。

### 代价与限制

- 两个站点若依赖白名单之外的 CDN、统计、广告或图片资源，相关页面功能可能缺失。
- 部分外链无法在内置浏览器中打开，用户需要回到站内内容或使用其他独立方式访问。
- 必须验证 WebView 对重定向的拦截时机和原始 HTTP 状态码可见性，可能需要更深入的网络层拦截实现。
- 站点新增子域名可自动纳入允许范围，因此白名单策略依赖两个域名树自身的安全性；仍需持续使用 WebView 沙箱和最小权限原则。
- 浏览器用户数据、Cookie 和缓存仍需独立管理，白名单并不替代浏览器运行时安全更新。

## 验收标准

- zh.minecraft.wiki、mcmod.cn 及各自任意层级的子域名 HTTPS 页面可以访问。
- zh.minecraft.wiki.example.com、evil-zh.minecraft.wiki、mcmod.cn.example.org 等相似域名被拒绝。
- 非 HTTPS 协议、用户信息欺骗、危险协议及无法规范化的 URL 均被拒绝。
- 地址栏显示当前完整 URL，允许复制，但不能编辑、粘贴、搜索或直接导航。
- 两个允许域名树之间的站内跳转正常工作。
- 所有外部顶层导航均由 ECL 拦截，并显示 ECL 本地错误页面；不得请求外部目标。
- 外部 3xx 重定向在跟随前被阻止，错误页显示真实 3xx 状态码、原始 URL 和被拒绝的目标 URL。
- 允许域名树内的重定向逐跳校验，任何一跳离开白名单都立即拒绝。
- 子资源、iframe、脚本、样式、图片、字体和 fetch/XHR 等请求均不能访问白名单之外的域名树。
- 新窗口请求不会创建不受控 WebView；通过检查的站内目标在当前受控上下文打开。
- 弹窗、下载、外部协议和敏感权限默认拒绝。
- 错误页面由 ECL 本地生成，不从被拦截站点加载资源。
- WebView 不具备任意访问 ECL/.NET 对象、本地文件或启动器管理功能的能力。
- 浏览器运行时失败或访问被拒绝不会影响 ECL 的普通功能和 Minecraft 启动。
- ECL 不通过服务器代理、镜像或抓取方式转发第三方网页内容。
