# ADR 0022：存储空间分析与安全清理中心

> 生命周期迁移说明：本次仅拆分决策与实施状态，不改变既有技术决策；尚未开始实施的提案保持原有阶段。

- Decision: Proposed
- Implementation: In Progress
- Date: 2026-11-02
- Scope: ECL 存储空间统计、下载缓存、运行缓存、实例数据清理与实例删除交互

## 背景

ECL 同时管理自身程序数据、下载产物、Java Runtime、Minecraft 工作区以及用户登记的外部实例。随着实例、模组、资源和日志不断增加，用户难以判断磁盘空间被哪些内容占用，也缺少统一且可信的清理入口。

清理功能不能简单等同于“扫描大文件并删除”。Minecraft 实例目录中可能混合存在世界存档、模组、配置、资源包、截图、日志和可重建缓存。仅凭文件名、扩展名或目录大小无法可靠判断用户数据是否重要。错误清理可能造成不可逆的数据丢失。

## 决策

ECL 提供统一的“存储与清理”功能，负责解释空间占用、提供受控清理动作，并明确区分缓存回收和实例删除。

### 1. 展示 ECL 与 Minecraft 的空间占用

清理中心至少展示 ECL 程序与自身数据、ECL 下载缓存及临时下载产物、Java Runtime、Minecraft 工作区与已登记实例来源，以及其他可识别但不由 ECL 管理的占用。最后一类仅统计，不提供默认删除动作。

空间统计应区分已扫描大小、估算大小、无法访问或尚未扫描。不得把未知目录显示为 0，也不得把逻辑文件大小冒充实际磁盘占用。统计应支持刷新，目录遍历不得在 UI 线程执行；扫描过程中应显示进度或状态，取消扫描不得影响文件。

### 2. Minecraft 占用按实例来源分组

Minecraft 空间应按用户登记的实例来源根目录分组，再显示该来源下的实例及其占用。例如：

- HMCL — 9 GB
  - 1.20.1 — 500 MB
  - 1.21.1 — 700 MB
- PCL — 3 GB
  - 1.12.2 — ...

该分组复用 ADR 0023 的多来源实例目录模型。来源组可折叠；展开后列出实例。无法归属到某个实例的共享文件应单独显示为来源级公共数据，不能任意摊派给某个实例。

### 3. 清理目标采用程序定义的安全白名单

清理器不得提供“选择任意文件夹并递归删除”的通用能力。可清理范围由 ECL 代码中的集中式清理策略定义，按数据类别提供明确的路径解析、所有权判断、活动状态保护和删除规则。

可纳入清理策略的典型内容包括：ECL 可重新生成的缩略图、索引和临时解压目录；已完成且不再被引用的下载缓存；ADR 0020 定义的、超过保留期限且不属于活动任务的下载临时产物；已确认不再使用的安装或更新暂存文件；实例中可安全重新生成且由 ECL 明确识别和管理的缓存；实例历史日志及诊断临时文件。

上述类别不是对任意同名目录的授权。每一种清理项必须有明确的数据所有者、识别规则和删除边界。遇到未知结构、符号链接、路径越界、权限异常或归属不明时，应跳过并报告，不能猜测。

### 4. 用户数据默认受保护

默认禁止自动清理以下内容：

- 世界存档及其备份；
- 模组、插件、数据包；
- 用户配置、按键设置、服务器列表；
- 资源包、光影包、材质及用户下载内容；
- 截图、录屏、自定义文件；
- 用户放入实例目录中的其他未知文件。

清理中心不得仅凭文件位于 .minecraft 或某个实例目录中，就认为它属于缓存。无法可靠分类的文件一律按用户数据处理。

ECL 应明确提醒用户：实例目录是用户数据区域，不应存放与 Minecraft 无关的重要个人文件；ECL 的清理策略仅针对界面明确列出的受支持类别，不承诺保护用户自行放入受管理目录的任意文件。该提醒不能代替程序层面的白名单保护。

### 5. 实例缓存与日志按实例独立清理

对可识别实例，提供实例级清理入口，至少可分别查看和清理符合白名单规则的缓存、该实例的历史日志、诊断临时文件（若存在且已不再被活动会话引用）。

清理项应展示类别、预计可释放空间、涉及路径范围和可能影响。不得把“清理日志”与“清理实例”合并为一个含糊动作。当前运行实例、活动日志会话、仍被下载或安装任务引用的文件必须受到保护。清理前应再次验证目标身份和活动状态，防止扫描后路径内容变化导致误删。

### 6. 清理实例等同于删除实例，必须独立授权

清理中心允许用户直接删除实例，其语义与实例管理界面中的“删除版本/实例”完全一致，不得实现第二套更宽松的删除逻辑。

实例删除必须满足：

- 默认不勾选任何实例；
- 不提供默认全选实例的行为；批量操作也必须由用户逐项明确选择；
- 来源分组的折叠或展开不得改变选择状态；
- 明确显示实例名称、来源目录、完整路径和预计删除大小；
- 明确警告删除会移除整个实例及其中的世界存档、模组、配置和其他用户数据；
- 用户必须经过额外确认，不能与普通缓存清理共用一次确认；
- 活动实例或被活动会话占用的实例不得直接删除，应先要求安全退出或说明无法删除的原因；
- 删除外部实例前必须再次确认其真实路径，不能因来源目录名称相同而误删其他实例。

如果产品支持回收站或备份，应明确其实际行为和失败边界；在没有可靠恢复机制时，必须将操作标注为不可逆删除，不得暗示可以撤销。

### 7. 清理预览与执行必须分离

用户发起清理后，先生成清理预览，再执行删除。预览至少包括清理类别、预计释放空间、目标数量、涉及的实例或来源、跳过项目及原因，以及是否包含不可逆的实例删除。

执行阶段应逐项记录成功、跳过和失败。部分失败不能被报告为全部成功。清理操作不得阻塞 UI，也不得在 UI 线程执行文件系统操作。

### 8. 路径安全与并发保护

所有待删除路径必须经过规范化，并验证仍位于对应数据所有者的允许范围内。必须防范路径穿越、重解析点或符号链接逃逸、路径替换竞态和根目录误删。

清理器不得删除正在使用的文件。对无法安全判断占用状态的目标应跳过，而不是强制终止进程或强行删除。

清理策略应具备版本化或可测试的规则定义；新增清理类别必须经过单独评审和测试，不能通过扩大通配符范围悄悄改变清理行为。

### 9. 统计结果与可释放空间的语义

界面应区分当前占用、可清理空间、预计释放空间和已释放空间。硬链接、重复引用、共享目录、无法访问文件和扫描期间发生变化的文件应避免重复计数或给出估算标记。统计结果不是删除授权。

### 10. 与 ADR 0020、0023 的关系

- ADR 0020 定义下载临时产物的生命周期；本 ADR 的清理中心调用其规则，不得另行发明冲突的临时文件清理策略。
- ADR 0023 定义多个实例来源根目录的登记、扫描和分组；本 ADR 复用其来源与实例身份。
- 本 ADR 不改变实例存储位置，不擅自迁移外部实例，也不改变工作区选择规则。

## 后果

正面影响：用户能够理解 ECL 与 Minecraft 的空间占用来源；缓存、历史日志和过时下载产物拥有统一清理入口；白名单降低误删世界存档和用户文件的风险；实例删除与普通缓存清理明确分离。

代价：需要为不同数据所有者维护清理策略和路径安全验证；目录扫描需要处理性能、权限、重复计数和并发变化；实例删除需要复用统一删除服务，并处理活动会话和外部路径；UI 需要呈现分组、预览、警告和部分失败状态。

## 验收标准

1. 清理中心分别展示 ECL 与 Minecraft 的空间占用，并明确标注统计状态。
2. Minecraft 占用按实例来源根目录分组，展开后显示实例名称和大小。
3. 来源级共享数据不会被错误计入某个具体实例。
4. 所有自动清理目标均来自集中定义的白名单策略，不存在任意目录递归删除入口。
5. 世界存档、模组、配置、资源包、截图和未知文件不会被自动清理。
6. 实例缓存、历史日志和诊断临时文件可以按实例独立预览与清理。
7. 活动会话、活动下载、安装任务引用的文件不会被清理。
8. 清理前展示目标类别、预计释放空间和影响范围；执行后区分成功、跳过和失败。
9. 实例删除默认不选择任何实例，不提供默认全选；必须展示完整路径、影响范围并经过额外确认。
10. 清理中心删除实例与实例管理界面使用相同的删除服务、保护规则和结果语义。
11. 路径穿越、符号链接逃逸、路径替换竞态、权限不足和文件占用等场景不会导致越界删除。
12. 扫描和清理不会阻塞 UI；取消扫描不会改变文件，清理执行状态可被观察。
13. 清理中心明确提醒用户不要在实例目录存放重要个人文件，并说明未知文件默认不会被清理。
14. 统计结果能够区分占用大小、可清理大小、预计释放大小和实际释放大小。
