# ADR 0044：本地优先网络诊断 Addition 与数据主权

- Decision: Proposed
- Implementation: Not Started
- Date: 2026-11-03
- Scope: ECL 网络诊断能力、可选 Addition、诊断数据生命周期与用户隐私边界
- Related: [0032 原生功能入口与按需 Additions 扩展体系](0032-native-feature-interfaces-and-optional-additions.md)、[0033 本地 Minecraft 全面诊断与知识引擎](0033-local-minecraft-diagnostic-and-knowledge-engine.md)

## 背景

Minecraft 启动器依赖多个外部服务完成资源查询、版本元数据获取、文件下载和知识访问。用户遇到连接失败或响应缓慢时，需要能够区分 DNS 解析、TCP 连接、TLS 握手和 HTTP 请求等阶段的问题，并了解不同服务的实际可达性与响应延迟。

拟议的网络诊断能力包括对 CurseForge、Modrinth、Minecraft Wiki、MC百科、GitHub 等 Minecraft 生态相关服务进行连通性与延迟检测。该能力适合作为独立 Addition 提供，而不是让基础启动流程依赖一个常驻网络监控模块。

本能力不以测量用户带宽为目标。下载测试文件、调用 Speedtest 或自建测速节点会产生额外流量，也会引入服务器运营、服务许可、网络成本和计费网络保护等复杂度。用户已明确不需要主动测速。

ECL 的数据原则是：**ECL 不收集用户信息，用户数据均保存在本地。** 网络诊断必须遵循这一原则，不能以诊断、质量改进或故障排查为由建立遥测、行为追踪或诊断数据回传机制。

## 决策

### 1. 网络诊断作为可选 Addition

1. 网络诊断以独立的 Network Diagnostics Addition 提供。
2. Addition 负责诊断界面、检测编排、目标服务配置、结果呈现与本地历史记录。
3. Core 可提供稳定、受限的网络诊断能力接口，以及 ECL 当前网络请求所使用的代理与连接配置；不得要求普通启动流程依赖该 Addition。
4. Addition 未安装、被禁用或运行失败时，不得影响 Minecraft 的正常启动、下载和其他基础功能。
5. 诊断按需执行，不建立常驻后台监控，不通过持续轮询收集网络状态。

### 2. 只进行必要的连通性与延迟检测

1. 诊断范围包括 DNS 解析、TCP 连接、TLS 握手和 HTTP 请求等阶段。
2. 对每个目标分别呈现可达状态、阶段耗时、总响应耗时、超时或失败原因；在适用时记录 HTTP 状态码。
3. 可对轻量请求进行有限次数的重复采样，以呈现最小值、平均值、最大值和失败率。采样次数、超时和并发必须受控，避免对第三方服务造成不必要负载。
4. ICMP Ping 不得作为唯一连通性判断依据。目标屏蔽 ICMP 不代表其 HTTPS 服务不可用。
5. HTTP 403 等服务端拒绝响应，表示请求已到达服务端，不得简单归类为网络不可达；应保留状态码并说明应用层拒绝。
6. 目标服务可按站点/API/CDN 等实际访问入口拆分，例如 CurseForge、Modrinth、Minecraft Wiki、MC百科和 GitHub 的相关域名。目标列表应可维护，不将单一域名的结果推断为整个服务生态的可用性。
7. 诊断结果描述的是当前设备到特定目标、经特定网络路径的访问情况，不应将其夸大为用户整个互联网连接的绝对质量评分。

### 3. 不提供主动下载测速

1. 不实现主动带宽测速，不下载专用测试文件，不建立 ECL 测速服务器，也不将 Speedtest 或其他第三方测速服务作为诊断依赖。
2. 不为获得吞吐量指标而额外产生网络流量。
3. 正常业务下载过程中产生的下载速度属于下载任务自身的运行信息，不属于本 ADR 定义的主动测速功能；是否在下载界面展示该信息由下载功能自身决定，不得据此建立用户数据回传。
4. 不因网络连接被识别为不限量、计量或漫游网络而自动发起额外下载请求。

### 4. 本地数据主权与禁止回传

1. 网络诊断产生的结果、历史记录、目标配置、时间戳、错误详情和用户偏好均保存在本地设备。
2. ECL 不收集用户信息，不建立遥测、行为追踪、使用统计或诊断报告回传机制。
3. 不得将诊断结果、日志、网络环境信息、代理配置、设备标识或用户操作记录自动上传至 ECL 开发者控制的服务或第三方分析服务。
4. 不得以“帮助改进产品”“自动故障分析”“匿名统计”或类似理由绕过上述限制。
5. 本地诊断数据的保留、清理、导出和删除由用户控制；除用户明确发起且另有独立设计与授权的外部操作外，不离开本地设备。
6. 本地保存不意味着诊断数据可以被任意 Addition 读取。数据访问仍须遵循 Addition 权限和 Core API 的最小授权边界。

### 5. 第三方网络通信的透明边界

1. 为检测外部服务，ECL 必须向被测目标发送必要的 DNS 查询及网络请求。目标服务及网络中间设施可能因此获得正常网络通信所必需的连接元数据，例如来源 IP、请求时间和请求路径。
2. 这种由目标服务接收的必要通信元数据，不等同于 ECL 收集用户信息或将诊断数据回传给 ECL。
3. 诊断请求应尽量使用无身份认证、无个人账户上下文的轻量公开入口；不得为了诊断主动附加用户凭据、账户令牌或与检测无关的个人信息。
4. 不得通过诊断请求上传本地诊断历史、设备指纹或用户环境快照。
5. 当检测目标需要身份认证或会触发非只读业务行为时，不得将其作为默认连通性探测目标。

### 6. 代理与真实业务路径

1. 诊断应支持检测 ECL 当前业务所使用的代理路径，以便结果能够解释实际下载或 API 访问体验。
2. 结果必须标明检测使用的网络路径或代理模式；不得把代理路径的结果冒充为直连结果。
3. 若提供直连与代理对比，必须由用户明确发起，并分别呈现结果。
4. 诊断实现应尽可能复用 ECL 的网络栈与连接配置，避免诊断路径和真实业务路径存在不必要差异。
5. 诊断不得擅自修改系统代理、ECL 代理配置、DNS 配置或网络适配器设置。

## 备选方案

### 方案 A：将网络诊断作为核心内置功能

优点是无需安装 Addition，入口统一。

缺点是会扩大基础应用的职责和维护范围；网络诊断并非普通启动必需能力，不应因此增加核心界面和基础依赖。

**不采用。** 采用独立 Addition，Core 只提供必要的稳定能力接口。

### 方案 B：使用 Speedtest 或自建节点进行主动测速

优点是可以得到吞吐量数值，并形成单一的网络速度指标。

缺点是会额外消耗用户流量，需要测试节点或第三方服务，涉及服务许可、可用性、运营成本和计量网络保护；测试节点的速度也不能代表用户访问 CurseForge、Modrinth 或 GitHub 的真实体验。

**不采用。** 本项目只需要针对实际目标服务的连通性与延迟诊断，不主动下载测速数据。

### 方案 C：仅使用 ICMP Ping

优点是实现简单、数据量小。

缺点是大量服务或网络会屏蔽 ICMP，Ping 结果不能说明 HTTPS、API 或 CDN 是否可用，也无法区分 DNS、TCP、TLS 和 HTTP 阶段的问题。

**不采用。** 以实际业务协议的轻量请求为主要检测方式，ICMP 不作为唯一依据。

### 方案 D：上传匿名诊断数据以改善服务

优点是开发者可以集中分析故障趋势。

缺点是与 ECL 不收集用户信息、数据仅保存在本地的原则冲突；所谓匿名化也不能改变自动回传的事实。

**不采用。** 不建设诊断遥测或自动回传机制。

## 后果

### 正面影响

- 网络诊断能力与基础启动流程解耦，用户可按需安装和使用。
- 能够定位 DNS、TCP、TLS、HTTP 等阶段的故障，而不只是显示一个 Ping 数字。
- 检测针对实际 Minecraft 生态服务，结果更接近用户真正关心的访问体验。
- 不产生主动测速流量，不需要维护测速服务器，也不会因测速意外消耗计量网络套餐。
- 诊断结果与历史记录留在本地，符合 ECL 的数据主权原则。
- 通过代理路径检测时，能够更准确地解释 ECL 实际业务访问情况。

### 代价与风险

- 不提供带宽吞吐量数值，无法回答用户网络的理论下载速度。
- 第三方服务可能限流、屏蔽探测请求或返回非典型状态码，诊断必须区分网络层失败与应用层拒绝。
- 不同地区、DNS、代理、CDN 节点和网络时段会影响结果；单次检测不能代表长期服务质量。
- 目标服务域名和探测入口需要维护，第三方站点变更可能导致探测配置过期。
- 本地历史记录仍需考虑容量上限、保留策略和用户清理能力。
- 诊断请求本身仍会与第三方目标建立正常网络通信；ECL 无法保证第三方不记录其收到的连接元数据。

## 验收标准

1. 网络诊断可作为独立 Addition 安装、禁用和卸载；其不可用不影响普通启动与下载。
2. 至少能够区分 DNS、TCP、TLS、HTTP 阶段的成功、失败、超时或不适用状态。
3. 对 HTTP 403 等服务端响应能够保留状态码，不将其误判为网络不可达。
4. ICMP 被屏蔽但 HTTPS 可用时，诊断结果不得报告目标整体不可达。
5. 对多个目标的结果分别记录，不以单个站点结果推断整个服务的状态。
6. 诊断请求次数、超时和并发具有明确限制，不执行无限重试或持续轮询。
7. 不存在主动测速文件下载、Speedtest 调用或 ECL 测速节点依赖。
8. 诊断数据与历史记录保存在本地；自动诊断流程不向 ECL 或第三方分析服务上传数据。
9. 诊断请求不附加账户令牌、用户凭据、设备指纹或本地诊断历史。
10. 诊断结果明确标识所使用的代理/网络路径；不得静默修改系统或 ECL 网络配置。
11. 用户能够查看、清理本地诊断历史；Addition 不得越权读取其他模块的非必要数据。
12. 对第三方服务收到必要连接元数据的事实，在隐私说明中作出准确区分，不宣称外部网络请求完全不可见。
