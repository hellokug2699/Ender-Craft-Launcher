# ADR 0046：实例稳定身份与元数据模型

- Decision: Proposed
- Implementation: Not Started
- Date: 2026-11-03
- Scope: InstanceId、实例元数据、路径变化、迁移、克隆、外部实例关联与身份恢复
- Related: [ADR 0018：Minecraft 工作区与实例存储位置](0018-minecraft-workspace-and-instance-storage.md)、[ADR 0023：多实例来源目录登记与统一扫描](0023-multi-root-instance-discovery.md)、[ADR 0045：原生 Instance Engine 架构与能力边界](0045-native-instance-engine-architecture.md)

## 背景

实例可能被移动到其他磁盘、重命名目录、从其他启动器导入，或被复制为测试环境。若只使用路径、目录名、Minecraft 版本或实例显示名称作为身份，路径变化会造成身份丢失，同名实例会互相冲突，克隆也可能错误继承原实例的历史和事务记录。

ECL 需要将实例的逻辑身份与其当前物理位置分离，同时兼容没有 ECL 元数据的外部实例。

## 决策

### 1. 每个受 ECL 管理的实例拥有稳定 InstanceId

InstanceId 是实例的逻辑身份，不由目录名、路径、版本号或显示名称推导。创建或首次正式登记时生成唯一 ID，并在实例生命周期内保持稳定。

路径是实例当前位置，可变且可能不可访问；来源 ID 是发现/登记关系；显示名称仅用于 UI。三者不得替代 InstanceId。

### 2. 身份与位置分离

Engine 应分别保存：
- InstanceId；
- 当前规范化路径及路径可用状态；
- 所属来源/工作区登记关系；
- 用户可编辑的显示名称；
- 元数据 schema 版本；
- 创建时间与首次登记时间；
- 最近验证时间及身份验证状态。

不得把路径作为数据库主键。路径改变时更新位置关系，不应自动创建一个新实例身份。

### 3. 实例内保存轻量身份标记

对于 ECL 可写且已受管理的实例，采用实例目录内的轻量标记文件：

```text
.minecraft/
└── .ecl/
    └── instance.json
```

该文件只保存跨位置识别所必需的身份和格式元数据，例如 InstanceId、schema version、创建时间及必要的完整性字段。不得将完整 Inventory、扫描缓存、日志、事务历史或大型快照默认写入实例目录。

对外部只读实例或用户未授权修改的目录，不得为了登记身份而强制写入标记文件。此类实例可由 ECL 本地登记映射管理，并明确标记其身份锚点仅存在于本地。

### 4. ECL 本地数据库保存管理状态

ECL 本地数据目录保存实例身份映射、路径历史、来源关系、扫描索引、事务记录和其他派生状态。实例内标记与本地记录共同用于识别，但二者不应互相覆盖。

若标记文件缺失、损坏、重复或与本地记录冲突：
- 不得静默生成新身份覆盖旧关联；
- 不得仅凭名称、版本或文件相似度自动合并；
- 应显示冲突证据并要求用户确认；
- 能够可靠确认路径变化时，可提供重新定位/关联操作；
- 无法确定时保留为待确认对象。

### 5. 迁移与克隆采用不同身份语义

- **迁移（Move / Relocate）：** 原实例移动到新路径，保留 InstanceId；迁移过程必须验证源与目标内容及标记一致。
- **克隆（Clone）：** 从原实例创建独立副本，必须生成新的 InstanceId；不得复制原实例的事务锁、活动会话、恢复标记或独占身份状态。
- **备份恢复：** 恢复到原实例时可保留身份，但必须处理当前目录是否已存在同一 InstanceId 的冲突；恢复为并行副本时必须生成新身份。
- **外部实例导入：** 用户授权后登记；如果没有可信 ECL 标记，首次登记时创建本地身份映射。是否写入实例标记由用户授权和目录可写性决定。

### 6. 防止身份复制与路径别名冲突

扫描发现多个目录包含相同 InstanceId 时，不得把它们都当作同一实例的可同时写入位置。Engine 应检查路径规范化、文件系统对象身份（平台可用时）和标记内容，识别重复副本或路径别名。

若无法可靠区分移动残留、备份副本和克隆副本，应标记身份冲突并暂停写操作，允许只读检查和用户明确选择保留/重新生成身份。不得仅凭最后修改时间自动决定哪个目录是真实实例。

### 7. 身份元数据的安全与兼容

标记文件采用明确 schema version，支持向前识别未知版本并保守降级。解析时限制文件大小、字段数量和深度；内容视为不可信输入，不执行其中代码或路径指令。

标记文件不包含账户凭据、访问令牌、用户秘密或不必要的设备标识。InstanceId 不应被用作远程跟踪标识；ECL 不上传该 ID。

## 备选方案

### 方案 A：使用规范化路径作为唯一身份

实现简单，无需写入元数据。

放弃原因：移动、重命名和磁盘盘符变化都会改变身份；路径别名也可能造成重复登记。

### 方案 B：使用名称、版本和目录特征组合推断身份

可兼容外部实例，无需修改文件。

放弃原因：多个实例可能完全同名同版本；文件内容变化也会影响推断，无法作为可靠身份。

### 方案 C：稳定 InstanceId + 本地映射 + 可选实例内标记

选择原因：同时支持路径变化、外部只读目录和跨位置识别，并将克隆语义明确化。

## 后果

### 正面影响

- 路径变化不再意味着实例身份变化；
- 同名实例可安全并存；
- 迁移、克隆、快照和历史记录拥有清晰语义；
- 外部实例无需强制改写即可登记。

### 代价与风险

- 需要维护标记文件 schema 与本地映射一致性；
- 用户手动复制目录可能复制 InstanceId，必须有冲突检测；
- 外部只读实例无法仅靠目录标记跨 ECL 安装迁移身份；
- 身份恢复必须提供用户确认流程，不能依赖启发式猜测。

## 验收标准

1. 每个受管理实例有唯一且稳定的 InstanceId。
2. 实例移动或重命名后，重新定位可保留原 InstanceId。
3. 克隆实例获得新 InstanceId，且不继承原实例的事务锁和活动会话。
4. 同名、同版本但不同路径的实例可并存。
5. 同一 InstanceId 出现在多个独立目录时，写操作被暂停并显示冲突。
6. 外部只读实例可在不写入目录的情况下登记。
7. 标记缺失、损坏、未知 schema 或本地记录冲突时，不会静默覆盖身份。
8. 标记文件不包含凭据或用户秘密，也不触发网络传输。
9. 路径、来源 ID、显示名称和 InstanceId 在数据模型中明确区分。
