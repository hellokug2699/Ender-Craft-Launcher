# ADR 0026：实例工作台的存档、多人游戏与最近访问

- Status: Accepted (implementation pending)
- Date: 2026-11-02
- Scope: 实例工作台、本地世界存档、多人游戏服务器列表、主页最近访问

## 背景

ECL 当前以 Minecraft 实例为核心组织游戏安装、Java、Mod、资源和启动流程。实例目录不仅包含游戏版本与组件，也承载玩家自己的世界存档和多人游戏服务器列表。

用户在不启动游戏的情况下，仍然有管理这些内容的需求：

- 查看本地世界存档及其基本信息，打开目录、备份或删除存档；
- 查看实例中已保存的多人游戏服务器，查询服务器在线状态、人数、介绍、版本和延迟；
- 从主页快速回到最近查看或访问的存档与服务器。

这些能力适合放在实例工作台，而不是将大量管理逻辑堆入主页。主页负责展示少量最近访问摘要和快捷入口；实例工作台负责完整管理。

ECL 已有按进程隔离的游戏会话记录，但“最近启动”与“最近访问”不是同一概念。用户可能只查看存档详情或查询服务器状态，并没有启动游戏。因此需要将最近访问作为独立的本地活动记录处理。

## 决策

### 1. 实例工作台扩展为游戏环境管理入口

实例工作台围绕单个 Minecraft 实例组织以下内容：

- **存档管理：** 查看该实例可访问的世界存档、存档详情及安全管理操作。
- **多人游戏：** 读取该实例的服务器列表，查看服务器信息并主动查询在线状态。
- **现有内容管理：** 延续 Mod、资源包、光影包、数据包等已有管理能力。
- **游戏日志：** 延续按会话查看日志、崩溃分析和诊断导出能力。

这些模块应保持职责独立，通过实例上下文协作。不得把存档解析、服务器网络查询和最近访问持久化直接塞入主页 ViewModel。

### 2. 存档管理以本地只读发现为默认行为

ECL 应从当前实例实际使用的 Minecraft 游戏目录中发现存档，不得假定所有实例都使用固定目录布局。需要考虑实例隔离、用户指定的游戏目录、外部实例以及共享 .minecraft 目录。

存档列表和详情可以读取 Minecraft 世界元数据，例如：

- 存档显示名称及目录名称；
- 世界图标（如存在）；
- Minecraft 版本及可获得的版本信息；
- 游戏模式、难度等世界设置；
- 游戏内时间等元数据；
- 最后修改时间和本地存档占用空间。

字段是否存在取决于存档版本和 level.dat 内容。缺失、损坏或未知字段不得导致整个存档列表失败；应显示可用信息，并标记无法读取的字段。解析必须兼容不同 Minecraft 版本的 NBT 结构，不得假定单一固定格式。

默认浏览和查看操作只读，不应修改世界文件或启动 Minecraft。

### 3. 存档危险操作必须明确且可恢复

存档管理可逐步提供：

- 查看存档详情；
- 打开存档目录；
- 备份存档；
- 从备份恢复；
- 删除存档。

删除前必须明确展示存档名称和实际目标路径，并要求用户确认。不得因实例删除、实例切换或其他清理操作而隐式删除世界存档。

备份应尽可能采用临时目标写入、完成后再提交的方式，避免中断时留下一个看似完整的备份。恢复或覆盖现有存档前必须再次确认目标，并建议先备份当前内容。

对共享目录、外部实例和用户指定路径，必须验证规范化后的目标仍位于该实例所授权的游戏目录范围内；不得跟随路径穿越或不受信任的链接而删除范围外文件。无法可靠确认目标边界时，应拒绝危险写操作，但仍可提供只读信息和打开目录入口。

存档大小统计和目录扫描应异步执行，并对异常文件、权限拒绝和扫描中断提供可解释状态。

### 4. 多人游戏列表读取本地 servers.dat

ECL 应读取当前实例对应的 Minecraft servers.dat，解析玩家已经保存的服务器条目。

可展示的信息包括：

- 玩家设置的服务器名称；
- 地址与端口；
- 服务器列表中的图标（如存在）；
- MOTD 或服务器介绍；
- 玩家收藏/隐藏等本地列表状态（若 Minecraft 数据格式提供）。

读取服务器列表默认只读，不应擅自修改、重排或删除 Minecraft 原有条目。未知 NBT 字段应尽可能保留在原始数据中；未来若实现编辑或写回，必须采用安全写入和备份策略，避免破坏 Minecraft 自己维护的列表。

### 5. 服务器状态查询采用 Minecraft Java Edition Server List Ping

ECL 可以在用户主动进入多人游戏管理页面、手动刷新或明确启用受控刷新时，对已保存的服务器执行 Java Edition Server List Ping（状态查询协议）。

在服务器支持且响应有效时，可展示：

- 在线/离线或查询失败状态；
- 当前在线人数与最大人数；
- MOTD；
- 协议版本及服务器报告的版本名称；
- 往返延迟；
- 服务器图标（如返回且通过尺寸与格式校验）。

查询不需要启动 Minecraft，也不需要用户登录 Minecraft 账户。服务器状态由远端服务器自行报告，可能不准确、过期或被伪造；ECL 应将其视为远端提供的信息，不应将其当作可信身份或安全证明。

查询流程必须满足：

- 网络 I/O 异步执行，不阻塞 UI 线程；
- 单个服务器具有有限连接与读取超时；
- 多服务器查询设置并发上限，避免瞬间向大量服务器发起连接；
- 对响应长度、JSON、图标尺寸和图像解码设置上限；
- 解析失败、超时、DNS 失败、连接拒绝和协议不兼容应区分或提供可理解的失败原因；
- 对结果进行短期缓存，允许用户手动刷新；不得默认高频持续轮询；
- 支持 Minecraft Java Edition 的 SRV 记录解析及默认端口规则；解析失败时应清楚显示原因，不得悄悄连接到无关地址；
- 不执行服务器返回的文本、链接或其他内容，不自动下载服务器提供的文件。

服务器地址来自用户本地配置，但仍属于不可信输入。应严格解析主机名、端口和协议字段，限制资源消耗，避免畸形地址、超大响应和恶意状态数据影响启动器稳定性。

### 6. 主页增加“最近访问”摘要

主页可在现有启动与运行环境区域之外，增加紧凑的“最近访问”区域，展示最近访问的存档和服务器，并提供快捷入口。

最近访问至少区分：

- **存档访问：** 用户打开存档详情或主动从主页/工作台进入某个存档；
- **服务器访问：** 用户打开服务器详情或主动查询某个服务器；
- **游戏启动：** 仍由现有游戏会话系统记录，不应与单纯查看存档或查询服务器混为一谈。

主页摘要可以显示实例名称、存档或服务器名称、必要的版本/地址信息和最近访问时间。服务器在线状态可以展示缓存结果及其更新时间，不应为了主页展示而持续后台轮询。

最近访问记录应支持跳转到对应实例工作台中的对象。对象已被删除、移动或无法访问时，应显示不可用状态并允许清理记录，不得自动重建对象或猜测新路径。

最近访问是本地辅助信息，不应成为主页的强制内容。没有记录时可以隐藏该区域或展示轻量空状态，不得用虚构示例填充真实用户界面。

### 7. 最近访问数据保存在本地

最近访问记录仅用于 ECL 本地导航和用户体验：

- 不自动上传给 ECL 维护者；
- 不作为遥测或用户画像数据；
- 不写入游戏存档或 Minecraft 的 servers.dat；
- 不应在记录中复制不必要的服务器密码、账户令牌或其他秘密；
- 应允许用户清空最近访问记录；
- 对服务器地址等可能具有隐私属性的信息，应避免写入普通诊断日志。

记录应包含稳定的实例标识和对象定位信息，并容忍实例目录移动、实例删除及对象不存在等情况。持久化格式应可版本化，读取失败时不能阻止 ECL 启动。

## 模块边界建议

建议以独立服务承载能力，具体命名可在实现阶段按现有项目约定调整：

- WorldSaveService：存档发现、元数据读取、目录打开、备份与删除。
- ServerListService：读取实例 servers.dat，提供服务器条目。
- ServerStatusService：执行 Server List Ping、缓存状态和管理并发/超时。
- RecentAccessService：记录、查询和清理最近访问。
- 主页 ViewModel：只消费上述服务提供的摘要，不直接解析 NBT 或发起网络协议。

上述服务应接受明确的实例上下文，避免隐式依赖当前选中实例或全局共享路径。网络查询和文件扫描均应支持取消，并通过可测试的接口隔离文件系统、DNS、TCP 和时间来源。

## 后果

### 正面影响

- ECL 从单纯的实例启动和内容安装工具，扩展为不启动游戏也能管理本地游戏环境的工作台。
- 玩家可以在一个地方查看存档和已保存的多人游戏服务器。
- Server List Ping 为服务器列表提供实时或短期缓存的状态信息，无需启动 Minecraft。
- 主页能够展示有实际用途的最近访问入口，而不是加入新闻、广告或无关内容填充空间。
- 存档、服务器、游戏会话与内容管理形成围绕实例的完整信息结构。
- 最近访问与游戏会话职责分离，避免把“查看过”误记成“玩过”。

### 代价与限制

- Minecraft NBT 格式会随版本演进，存档与服务器列表解析需要兼容性测试。
- 外部实例、共享目录和用户自定义路径增加文件边界与安全处理复杂度。
- Server List Ping 需要维护网络协议、SRV 解析、超时、并发和恶意响应防护。
- 服务器状态并非权威事实；离线、过滤、代理、防火墙或服务端配置都可能影响结果。
- 最近访问会保存存档和服务器的本地导航元数据，必须提供清理能力并避免不必要的日志暴露。
- 这些功能不应成为游戏启动的前置依赖；解析失败、网络不可用或服务器离线不能阻止用户启动本地实例。

## 实施顺序建议

1. 只读读取实例存档列表和基本元数据，覆盖不同 NBT 版本与异常存档。
2. 只读读取 servers.dat 并展示服务器名称、地址和图标。
3. 实现 Server List Ping、SRV、超时、并发上限、缓存和失败状态。
4. 实现存档详情、打开目录、备份与带确认的删除。
5. 实现本地最近访问记录，并接入存档和服务器详情入口。
6. 在主页增加最近访问摘要和快捷导航。
7. 后续再评估服务器收藏/编辑、备份恢复和更丰富的存档元数据。

## 验收要求

- 无需启动 Minecraft 即可读取存档和服务器列表。
- 不同实例使用各自正确的游戏目录；共享目录不会被误判为 ECL 私有目录。
- 缺失、损坏或未知版本的 level.dat / servers.dat 不会导致整个实例工作台崩溃。
- 只读浏览不会修改存档或服务器列表文件。
- 删除、恢复和覆盖操作有明确目标展示与确认；路径边界验证失败时拒绝危险写入。
- 多个服务器可并发查询，但 UI 不冻结，单个无响应服务器不会拖住整个页面。
- 对超时、DNS 错误、连接拒绝、无效 JSON、超大响应和无效图标有受控处理。
- 状态缓存有明确有效期和更新时间，页面打开不会触发无限或高频轮询。
- 最近访问正确区分存档访问、服务器访问和游戏启动，并能清理记录。
- 主页没有最近访问数据时保持简洁；最近访问区域不依赖网络才能打开主页。
- 所有最近访问数据保存在本地，不触发自动上传或遥测。
- 文件扫描、备份和网络查询均可取消，失败不会破坏原始数据。
