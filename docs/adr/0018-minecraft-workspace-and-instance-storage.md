# ADR 0018：Minecraft 工作区与实例存储位置

- Status: Completed
- Date: 2026-11-01
- Scope: Minecraft 实例根目录、工作区初始化、外部实例导入、存储迁移与数据保护

## 背景

Minecraft 实例包含游戏版本文件、模组、资源包、世界存档及其他大型内容。一个整合包可能占用数 GB 至数十 GB，多个实例的总量可能更高。用户通常希望将这些数据放在容量充足、便于访问或可移动的非系统盘，而不是程序安装目录、`ProgramData` 或不易发现的隐藏目录。

ECL 还需要保存自身配置、账户状态、日志和受管理 Java 运行时。这些数据的生命周期、访问方式和容量特征不同，不应与 Minecraft 实例混为一谈。

## 决策

### 1. 明确存储边界

ECL 将存储分为以下类别，彼此不得隐式合并：

| 类别 | 内容 | 默认位置与策略 |
|---|---|---|
| 程序安装目录 | Bootstrapper、版本化程序文件、部署状态 | `%LOCALAPPDATA%\Programs\Ender Craft Launcher`；允许用户在安装时更改 |
| ECL 用户数据 | 配置、账户状态/凭据、日志、应用数据库 | 当前用户 `%LOCALAPPDATA%\EnderCraftLauncher` 下按类别组织；敏感凭据遵循独立安全存储策略 |
| 受管理 Java 运行时 | ECL 下载或管理的 Java runtime | 当前用户数据根目录下独立的 `Runtimes` 目录；允许后续提供迁移设置 |
| Minecraft 工作区 | ECL 管理的实例、共享 libraries/assets、下载缓存及工作区元数据 | 首次启动由用户确认；优先推荐用户可见且空间充足的非系统盘位置 |
| 外部实例 | 用户已有的实例目录 | 保持原位置；通过导入/添加根目录登记，不要求复制或移动 |

程序安装目录与 Minecraft 工作区必须独立。安装、更新、回滚和卸载不得将工作区视为程序文件。

### 2. 首次启动时选择工作区，而不是在安装时强制决定

- 安装器只选择程序安装目录，不负责选择或初始化 Minecraft 工作区。
- 首次启动时展示清晰的工作区引导，解释该目录将存放实例与游戏资源。
- 用户确认前，不得开始下载游戏文件、创建完整工作区结构或迁移现有数据。
- 用户可以接受推荐位置，也可以选择其他本地磁盘、独立 SSD 或其他有写入权限的目录。
- 允许跳过并稍后配置，但在需要创建/下载第一个实例前必须确定有效的工作区。

### 3. 默认路径推荐与回退

- 默认推荐位置优先考虑非系统盘上常见、可见、用户可写的游戏目录，例如检测到的固定本地数据盘下的 `Games\ECL`。
- 若没有合适的非系统盘，不得擅自猜测或创建不存在的盘符；提供用户文档目录下的可见 `Games\ECL` 作为建议，或让用户显式选择位置。
- 不得将 `ProgramData`、程序安装目录、隐藏的 `AppData`、Windows 目录或磁盘根目录作为 Minecraft 工作区的默认推荐。
- 不得仅因 D: 不存在就静默回退到 C: 并开始下载。回退建议必须在 UI 中明确展示完整路径，并由用户确认。
- 路径检测需验证目录可创建、可写、剩余空间可读取；空间不足时警告，不得把空间检查当作对未来容量的保证。
- 可移动磁盘或网络路径可以作为显式选择，但需提示设备离线、网络中断、性能和可用性风险；默认推荐优先本地固定磁盘。

### 4. 支持多个实例根目录与外部实例

- 初期至少支持一个默认 ECL 工作区；数据模型和路径 API 不得将“单一根目录”写死为不可扩展架构。
- 后续支持登记多个 ECL 管理的实例根目录，并明确每个实例所属根目录。
- 支持添加/导入用户已有实例目录；导入默认只登记和验证，不复制、不移动、不重命名、不清理源目录。
- 导入前检查实例结构与路径权限；识别失败时给出原因，不擅自修复或覆盖。
- 实例路径必须作为显式元数据保存，不能仅凭实例名称拼接推导；处理路径时防止目录穿越和符号链接逃逸。

### 5. 工作区迁移必须是显式、可恢复的数据操作

- 迁移由用户主动发起，并在执行前展示源路径、目标路径、预计容量、涉及的实例数量和共享数据类别。
- 迁移前检查目标空间、写入权限、源/目标是否重叠以及游戏/启动器进程是否正在使用数据。
- 优先采用复制到目标、校验文件与元数据、原子切换工作区配置、保留源数据的流程；不以直接移动作为唯一策略。
- 迁移中断必须可识别并可恢复；迁移未验证成功前不得删除或修改源数据。
- 切换成功后保留源目录，提供用户自行确认清理的独立操作；ECL 不自动删除旧工作区。
- 不支持安全迁移的文件系统、网络位置或权限环境必须明确拒绝或降级为用户自行迁移指引。

### 6. 生命周期与数据保护

- 更新、回滚和修复程序文件不得扫描并清理 Minecraft 工作区。
- 卸载 ECL 默认只移除程序文件；不得删除用户配置、账户数据、日志、Java 运行时或 Minecraft 工作区。
- 用户请求删除工作区时，必须单独展示准确路径、实例/数据范围和不可逆后果，并要求明确确认。
- 任何清理功能必须使用登记的工作区/实例元数据限定目标，禁止通过宽泛的父目录递归删除来推断用户数据范围。
- 工作区不可访问、磁盘离线或盘符变化时，保留原路径登记并提示重新连接或重新定位，不得自动创建空目录冒充原工作区。

## 后果

### 正面

- 用户可以把大型 Minecraft 数据放在容量充足、容易访问的磁盘。
- 程序更新与实例数据生命周期隔离，降低误删和损坏风险。
- 外部实例导入无需强制复制大量文件。
- 迁移具备校验、恢复和保留源数据的安全边界。

### 代价与约束

- 首次启动需要工作区选择与路径可用性检查。
- 多实例根目录、外部实例导入和迁移需要显式数据模型与测试。
- 跨磁盘迁移耗时且需要额外临时空间。
- 可移动磁盘、网络位置和盘符变化需要更细致的错误状态与恢复体验。

## 验收标准

1. 程序安装路径、ECL 用户数据路径、Java runtime 路径与 Minecraft 工作区路径在配置和代码中明确区分。
2. 首次启动在下载/创建首个实例前要求用户确认工作区。
3. 默认推荐路径不会落入 `ProgramData`、程序安装目录或隐藏的 `AppData`；无合适非系统盘时显示明确回退建议并取得用户确认。
4. 用户可选择其他本地磁盘路径；外置/网络位置有明确风险提示。
5. 添加外部实例不会未经许可复制、移动或删除源数据。
6. 工作区迁移包含空间/权限检查、文件验证、中断恢复与源数据保留。
7. 更新、回滚、修复和默认卸载测试证明不会触碰工作区。
8. 不可访问的工作区不会被静默替换为空目录。
