# ADR 0029：Installer、Bootstrapper 与 Uninstaller 的生命周期边界

> 生命周期迁移说明：本次仅拆分决策与实施状态，不改变既有技术决策；原状态中的 implementation pending 明确映射为尚未开始实施。

- Decision: Accepted
- Implementation: Not Started
- Date: 2026-11-02
- Scope: ECL 在 Windows 上的安装、启动更新与卸载生命周期
- Related: ADR 0024（用户授权的自签名代码证书信任）、ADR 0025（Installer 首次启动完整性确认向导）

## 背景

ECL 需要明确安装、日常启动、更新和卸载各阶段的职责边界。随着 Bootstrapper 承担启动协调与更新工作，如果再将卸载功能直接嵌入 Bootstrapper，就会使卸载依赖一个可能正在被更新、损坏或本身就是卸载目标的组件。

卸载是安装生命周期中的独立操作，应尽可能在 ECL 主程序、Bootstrapper 或网络服务不可用时仍然能够完成。用户也不应因为卸载启动器而意外删除 Minecraft 实例、世界存档、模组或其他个人数据。

因此，ECL 采用三个职责独立的组件：Installer、Bootstrapper 和 Uninstaller。它们可以共享明确版本化的安装清单及安装元数据，但不得互相承担不属于自身生命周期的核心职责。

## 决策

### 1. 三个独立组件，各自负责一个生命周期阶段

ECL 将安装、启动/更新和卸载拆分为独立可执行组件：

- **ECL Installer：** 负责首次安装、修复安装、安装目录初始化、安装清单创建，以及 Windows 卸载入口注册。
- **ECL Bootstrapper：** 负责日常启动协调、版本检查、更新流程和主程序启动。它可以检测安装状态，但不负责实现完整卸载逻辑。
- **ECL Uninstaller：** 负责卸载预检查、卸载范围展示、用户确认、程序文件清理、系统注册信息清理和卸载结果报告。

Uninstaller 必须是独立可执行文件，不得仅作为 Bootstrapper 的子命令或依赖 Bootstrapper 进程内的卸载模块。Windows 的“应用和功能”或传统“程序和功能”卸载入口应直接启动 Uninstaller。

三个组件共享必要的安装元数据，但任一组件不可用时，不应让其他生命周期操作必然失效。例如 Bootstrapper 损坏不应阻止用户运行 Uninstaller。

### 2. 安装清单是卸载的权威边界

Installer 应在安装过程中创建机器可读的安装清单（例如 `install-manifest.json`）。清单至少应描述：

- 安装清单 schema 版本；
- ECL 产品标识、安装版本和安装范围；
- 安装根目录；
- 由 Installer 部署、且允许 Uninstaller 删除的程序文件；
- ECL 创建的快捷方式和系统注册项；
- 卸载器自身的位置及必要的恢复信息。

实际字段和格式可在实现阶段按仓库约定确定。

Uninstaller 必须以安装清单和经过校验的安装根目录为依据执行删除，不得通过宽泛的目录扫描、模糊名称匹配或递归猜测来决定删除范围。

路径处理必须防止路径穿越、重解析点/符号链接逃逸和清单篡改造成的越界删除。清单中任何路径都必须规范化，并验证其仍位于预期安装根目录或明确允许的 ECL 专属位置内。

如果清单缺失、损坏、版本不兼容或校验失败，Uninstaller 应停止自动删除并说明情况，提供安全的修复/手动处理指引；不得退化为“删除整个安装目录”或猜测文件归属。

安装清单不得把用户数据目录当作程序文件目录。安装目录中由用户自行放入、且不在可信安装清单中的文件默认不得删除。

### 3. 默认卸载只删除 ECL 程序，不删除 Minecraft 用户数据

卸载必须区分 ECL 程序文件与用户数据。默认行为如下：

| 内容 | 默认行为 |
|---|---|
| ECL 主程序及随安装部署的程序文件 | 删除 |
| ECL Bootstrapper | 删除 |
| ECL Uninstaller | 在卸载结束阶段清理 |
| Installer 创建的快捷方式 | 删除 |
| ECL 专属卸载注册信息 | 删除 |
| ECL 自己创建且明确登记的系统注册项 | 删除 |
| Minecraft 实例 | 保留 |
| 世界存档 | 保留 |
| 用户下载的模组、资源包、数据包 | 保留 |
| 用户配置及实例元数据 | 保留，除非用户另行选择清理 |
| 用户认证信息 | 默认保留或按独立数据策略处理；必须在 UI 中明确说明，不得静默扩大删除范围 |
| 日志、诊断文件及用户导出的诊断包 | 默认保留或提供单独清理选项 |

卸载 ECL 不等于删除 Minecraft 世界。不得因为用户卸载启动器而递归删除整个 `.minecraft`、实例目录、游戏目录或用户指定的数据路径。

如果未来提供“同时删除用户数据”选项，必须将其作为独立、明确、默认不选中的操作，逐项展示目标路径和数据类型，并在执行前再次确认。不能把它与普通卸载混为一谈。

### 4. 卸载流程必须可理解、可中止并尽可能可恢复

建议的卸载流程：

1. **预检查：** 检查 ECL 主程序、Bootstrapper 和相关子进程是否仍在运行；检查安装清单、安装目录及文件占用情况。
2. **范围展示：** 展示将删除的程序文件、快捷方式和注册信息，并明确说明实例、存档等用户数据默认保留。
3. **用户确认：** 用户明确确认后才开始删除。取消操作不得造成部分清理。
4. **执行卸载：** 按清单逐项清理；对文件占用、权限不足或清理失败的项目保留准确错误信息。
5. **清理注册信息：** 在程序文件清理成功或进入明确的部分卸载状态后，移除对应卸载入口和 ECL 创建的系统注册项。
6. **清理自身：** 由临时清理进程或受支持的延迟删除机制处理 Uninstaller 自身。
7. **结果报告：** 明确报告完全卸载、部分卸载或需要手动处理，不得在部分失败时显示卸载成功。

对于可能导致不可逆删除的步骤，应尽可能采用先验证、后提交的方式。卸载过程被中断或遇到错误时，下一次运行应能识别残留状态并继续安全清理，而不是把残留状态误认为完整安装。

### 5. Uninstaller 不依赖网络和 Bootstrapper

Uninstaller 的核心卸载流程必须完全本地化：

- 不要求访问 GitHub、更新服务器或其他网络服务。
- 不要求 Bootstrapper 正常运行。
- 不要求 ECL 主程序能够启动。
- 不要求 Microsoft、Minecraft 或第三方账号保持登录。
- 不得在卸载时下载新的卸载代码或执行远程脚本。

Uninstaller 应由 Installer 随安装包部署，并在安装清单中登记。卸载过程中不能临时从网络获取一个新的 Uninstaller 替代本地版本。

### 6. Windows 权限遵循最小权限原则

Uninstaller 默认以当前用户的普通权限运行，不主动请求管理员权限。

- 对安装在用户可写目录中的 ECL，正常卸载不应触发 UAC。
- Uninstaller 不得仅为了方便删除文件而默认提升权限。
- 如果安装位置或用户自行修改的文件导致权限不足，应准确说明无法删除的路径和原因，并提供人工处理方式。
- 只有确有必要且用户明确发起、并且有独立合理授权依据的操作，才可以评估额外权限流程；不得把普通卸载变成管理员权限入口。
- 本 ADR 不改变 ADR 0024 对 ECL 常规程序不得请求管理员权限的约束，也不扩大证书导入以外的权限授权范围。

Uninstaller 不应删除用户或其他软件创建的证书、系统信任设置、代理配置或全局环境配置。任何未来由 ECL 创建的系统级设置都必须有明确归属记录，并经过单独审查后才允许加入卸载清单。

### 7. Uninstaller 自身清理

Windows 不允许进程可靠地删除正在运行的自身可执行文件。Uninstaller 不应依赖直接删除当前 EXE 的行为。

实现可以选择：

- 在卸载末尾启动一个职责极简的临时清理进程，待 Uninstaller 退出后删除其文件；或
- 使用经过验证的 Windows 延迟删除机制。

无论采用哪种方案，临时清理逻辑都必须限制在已验证的 ECL 安装路径内，不得成为第二套通用卸载系统，也不得以管理员权限运行。清理失败时应留下可识别的残留状态并告知用户。

### 8. 更新与卸载之间必须避免竞态

Bootstrapper 更新和 Uninstaller 卸载不能同时修改同一安装目录。

- Uninstaller 开始执行后，应阻止新的 ECL 启动和更新任务进入。
- Bootstrapper 正在更新时，Uninstaller 应检测并提示等待或安全退出，不得强行删除正在替换的文件。
- 需要使用本地安装状态锁或等效同步机制，锁定范围应限于同一安装实例。
- 锁必须具备进程退出后的释放/失效处理，不能因为异常退出永久阻止卸载。
- Installer 修复安装、Bootstrapper 更新和 Uninstaller 应共同遵守安装清单的版本与写入规则。
- 不允许在更新过程中把半写入的安装清单当成可信卸载依据；清单更新应采用临时文件写入、校验后原子替换等安全方式。

## 建议的安装目录布局

以下仅为逻辑示例，实际目录和文件名可按仓库现有发布结构调整：

```text
ECL/
├── ECL.exe
├── ECL.Bootstrapper.exe
├── ECL.Uninstaller.exe
└── install-manifest.json
```

Installer 通常作为独立安装包分发，不要求常驻安装目录。安装目录布局不应强迫用户把 Minecraft 实例或世界存档放在 ECL 程序目录内。

## 不在本 ADR 中决定的事项

本 ADR 不决定：

- ECL 最终采用 per-user 还是 per-machine 安装作为唯一模式；
- 安装目录和用户数据目录的最终默认路径；
- 安装清单的最终 JSON schema；
- Uninstaller 的具体 UI 框架和视觉设计；
- 是否提供独立的“修复安装”入口及其完整交互；
- 未来是否提供删除用户数据的高级选项及其具体分类。

这些事项应在实现设计中结合当前仓库结构、Installer 技术选型和 Windows 实机测试确定，但不得违反本 ADR 的组件职责、数据保护和权限边界。

## 后果

### 收益

- Bootstrapper 损坏或不可用时，用户仍有独立卸载路径。
- 安装、更新和卸载职责清晰，组件之间不互相绑架。
- 卸载不依赖网络，降低服务不可用对用户控制权的影响。
- 安装清单限制删除范围，降低误删用户文件的风险。
- 默认保留实例和世界存档，符合启动器与玩家数据分离的原则。
- 普通卸载不扩大管理员权限范围。

### 成本与风险

- 需要维护独立 Uninstaller 的构建、签名、版本和兼容性。
- 安装清单必须有 schema 版本和严格的路径校验。
- 更新、修复安装与卸载需要协调并发状态。
- Windows 文件占用、权限差异和异常中断需要实机测试。
- Uninstaller 自身清理需要单独实现和验证。

## 验收要求

实施完成前至少验证：

- Installer 能正确部署 Uninstaller，并注册有效的 Windows 卸载入口。
- 不启动 ECL 主程序和 Bootstrapper，也能独立运行 Uninstaller。
- 网络断开时仍可完成卸载。
- Bootstrapper 损坏或缺失时，Uninstaller 仍能工作。
- 默认卸载不会删除实例、世界存档、模组、资源包或用户指定目录。
- 清单缺失、损坏、路径穿越、重解析点逃逸和未知文件均触发安全处理，不发生越界删除。
- 正在运行的 ECL 或更新任务能够被安全检测，不会发生并发删除。
- 文件占用、权限不足和中途退出会产生准确的部分卸载状态。
- 普通用户权限下可完成标准用户目录安装的卸载，且不触发 UAC。
- Uninstaller 自身能够在主流程退出后安全清理；失败时能提示残留文件位置。
- 卸载完成后，Windows 卸载入口和 ECL 创建的注册信息得到正确清理。
- 整个卸载流程不依赖在线服务，不执行远程代码。
