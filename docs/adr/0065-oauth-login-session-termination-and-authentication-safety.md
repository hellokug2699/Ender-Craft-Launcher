# ADR 0065: OAuth Login Session Termination and Authentication Safety

- Decision: Proposed
- Implementation: Not Started
- Date: 2026-11-08
- Scope: ECL Microsoft 正版账户 OAuth 登录会话的异常检测、立即终止、回调隔离、令牌交换中止与用户安全提示
- Related: [ADR 0037: Account Appearance and Local Wardrobe Architecture](0037-account-appearance-and-local-wardrobe.md)、[ADR 0052: Unified Dialog Engine and Incremental Migration](0052-unified-dialog-engine-and-incremental-migration.md)、[ADR 0053: Additions 能力权限模型与用户授权流程](0053-addition-capability-permission-and-user-consent.md)

## 背景

ECL 的 Microsoft 正版账户登录使用 OAuth 2.0 Authorization Code Flow with PKCE，并通过 localhost loopback redirect 接收授权响应。ECL 在本地创建一次性登录会话，生成 PKCE verifier、challenge 与 state，启动本地回调监听，并打开系统外部浏览器访问 Microsoft 授权端点。授权完成后，Microsoft 将授权响应重定向到该会话对应的本地回调地址；ECL 验证响应并使用对应 verifier 兑换令牌。

本 ADR 的首要问题不是识别互联网上所有冒充 ECL 的 OAuth 应用，也不是监视用户浏览器或系统网络流量，而是：**当 ECL 判断自己发起的登录会话出现异常、被取消或不再可信时，如何立即使该会话在 ECL 内部失效，并确保后续回调或迟到的令牌响应不能使其重新生效。**

PKCE 将授权码与本次客户端生成的 verifier 绑定；state 用于关联授权请求与回调。攻击者仅创建一个显示名称相同、Client ID 不同的 OAuth 应用，并不能因此接管 ECL 已经发起的 PKCE 会话。攻击者自己的授权流程具有独立的 Client ID、PKCE 参数、state 和回调目标。应用名称相同本身不是 ECL 会话被劫持的证据。

同时，PKCE 并不意味着所有风险都消失。本机程序可能干扰 loopback 回调或造成拒绝服务；回调可能迟到、重复、错配；用户可能取消登录；令牌兑换请求可能在取消发生时已经发出。ECL 必须对这些情况定义明确的会话终止语义，并避免把本地终止夸大为 Microsoft 服务器端授权撤销。

## 决策

### 1. 以一次性 OAuth 登录会话作为安全控制单位

每次用户主动发起 Microsoft 登录，都必须创建一个独立、不可复用的本地登录会话。会话至少绑定：

- 本次登录的内部会话身份；
- 预期 Microsoft 身份验证端点与固定 OAuth Client ID；
- 本次生成的 PKCE verifier / challenge；
- 高熵随机 state；
- 本次使用的 redirect URI、localhost 回调监听器及其生命周期；
- 本次登录的开始时间、截止时间与当前阶段；
- 本次令牌交换及账户状态提交的取消/完成状态。

不同登录尝试之间不得共享 verifier、state、回调监听器或可变认证状态。旧会话的回调不得被新会话接纳。一次性会话不得通过重置部分字段的方式复用；重新登录必须创建全新的会话与 PKCE 材料。

### 2. 将会话终止定义为本地强制失效操作

当用户取消登录、会话超时，或 ECL 检测到足以破坏本次授权关联性或完整性的异常时，必须将该会话原子地转入不可恢复的终止状态（Aborted / Terminated）。

终止操作应尽可能立即完成以下动作：

1. 先将会话标记为终止，使任何并发回调、令牌兑换完成回调和账户状态提交都无法再把它推进到成功状态。
2. 关闭本次 localhost 回调监听器，并停止接受该会话的新请求。
3. 取消尚未完成的令牌兑换操作；若底层网络请求无法可靠取消，仍必须丢弃其迟到结果。
4. 清除或释放本次会话的 PKCE verifier、state 及其他临时认证材料；对可安全清零的可变内存缓冲区执行尽力清理。不得声称运行时中所有不可变字符串或内存副本都能被绝对即时擦除。
5. 丢弃本次会话尚未提交的授权码、令牌响应及临时账户状态，不得将其写入账户凭据存储。
6. 记录不含授权码、verifier、令牌或其他秘密的终止原因与诊断信息。
7. 向用户明确报告本次登录已在 ECL 本地终止，并允许用户在需要时重新发起全新登录。

终止状态是终态，不允许恢复、续接或接受旧会话回调。重新尝试必须生成新的会话、state、verifier 和回调监听器。

### 3. 明确异常分类与终止触发条件

以下情况必须导致当前会话终止：

- 用户明确取消登录；
- 本次登录超过规定的有效时间；
- 本次会话的授权响应出现明确的 state 不匹配；
- 回调携带的授权响应无法与本次会话及其预期 redirect URI 关联；
- 检测到本次会话使用了非预期身份提供商或非预期 OAuth Client ID；
- 授权响应或令牌验证违反本次流程必须满足的协议约束；
- 本次会话的 PKCE 材料缺失、损坏、被替换，或无法证明授权码与本次 verifier 对应；
- 令牌兑换期间会话已被终止，或返回结果与本次会话不匹配；
- 其他经安全评审认定会破坏会话完整性、授权关联性或令牌归属的异常。

对明显不是 OAuth 回调的普通本地 HTTP 探测、无关路径访问或格式错误请求，应拒绝请求并记录必要的非敏感诊断信息，不应仅凭任意网络噪声就自动终止会话。否则，任何能够向本地端口发送请求的程序都可能轻易制造登录拒绝服务。对于看似针对当前回调、但无法通过会话关联验证的授权响应，必须拒绝该响应；是否同时终止会话，应依据其是否构成明确的会话完整性异常，而不能将普通探测与有效授权响应混为一谈。

终止策略不得为了减少误报而接受 state、PKCE 或 redirect URI 校验失败的授权结果。安全校验失败时，结果永远不能进入成功路径。

### 4. 处理回调与令牌兑换之间的竞态

会话终止可能与回调到达、令牌兑换请求发送、令牌响应返回或账户凭据持久化同时发生。实现必须保证终止优先级：

- 只有仍处于有效状态的会话才能接收并处理回调。
- 同一授权响应最多处理一次；重复回调不得重复兑换或重复提交账户状态。
- 令牌兑换开始前必须再次确认会话有效。
- 令牌兑换完成后、令牌写入账户凭据之前，必须再次确认会话仍有效且响应属于该会话。
- 如果终止先于账户状态提交生效，迟到的令牌响应必须被丢弃，不得重新激活会话或覆盖账户状态。
- 如果令牌已在终止发生前成功提交到账户凭据，则本地会话终止不能被描述为已经撤销该令牌；应按现有账户登出、凭据清理和服务端撤销能力处理，且不得承诺未被协议或服务支持的撤销效果。

取消网络请求是尽力行为，不等于服务器必然没有处理该请求。实现必须依靠本地终态检查阻止迟到响应生效，而不能只依赖 CancellationToken 或传输层取消结果。

### 5. 明确本地终止与 Microsoft 服务端撤销的边界

ECL 可以立即终止自己管理的本地登录会话、关闭自己的回调监听器、拒绝授权码和令牌响应，并阻止本次会话更新 ECL 账户状态。

ECL 不能保证关闭用户浏览器中的 Microsoft 页面，不能保证让 Microsoft 服务器端尚未完成的交互立即失效，也不能仅凭终止本地会话撤销用户已经授予另一个 OAuth Client ID 的权限或该应用已经取得的令牌。

若用户在攻击者自己的独立 OAuth 应用页面完成授权，该授权不属于 ECL 创建的会话。ECL 不会收到该应用的授权结果，也不能通过终止自己的会话撤销攻击者应用的授权。ECL 可以提示用户通过 Microsoft 官方账户安全与应用授权管理入口检查、撤销可疑授权，但不得宣称自己已检测到或自动撤销该外部授权。

### 6. 保持现有 PKCE 与 localhost loopback 架构，不引入无依据的浏览器监控

ECL 继续使用现有 Authorization Code Flow with PKCE 和 localhost loopback redirect。当前 Microsoft Entra 应用注册及实际登录流程已经使用 localhost；在没有验证兼容性、明确错误原因和安全收益之前，不得仅为形式上改用 127.0.0.1 或 [::1] 而破坏现有可用配置。

localhost、127.0.0.1 与 [::1] 的选择涉及主机名解析、地址族、监听行为及身份提供商配置兼容性。改变地址形式本身不能替代 PKCE、state、会话绑定或回调校验，也不能抵御已经能够在本机执行代码的攻击者。

回调监听器必须仅绑定 loopback 接口，不得监听所有网络接口；仅在本次登录会话期间开放；仅处理预期回调路径和方法；在成功、取消、异常或超时后关闭。实现应依据当前 Microsoft Entra 注册配置和实际 OAuth 库行为验证 redirect URI 的一致性，不得假设 localhost 与 IP 字面量在身份提供商注册中可以任意互换。

ECL 不应为此增加浏览器扩展、全局浏览器导航监控、TLS 中间人代理或系统级网络监听。ECL 可以记录自己构造并发起的授权请求，但这只能证明 ECL 自己请求了什么，不能证明用户浏览器当前展示的页面必然仍是该请求，也不能观察用户另行发起的独立 OAuth 流程。

### 7. 保留必要的用户安全提示，但不把应用名称核对当作核心防护

用户发起 Microsoft 正版登录时，ECL 应说明密码由外部 Microsoft 身份验证页面处理，ECL 不读取该密码；同时说明 ECL 会接收完成认证所需的授权结果和令牌。

提示应建议用户只继续处理由自己刚刚在 ECL 内主动发起的登录流程，不要通过陌生邮件、聊天消息或第三方网页提供的链接完成所谓 ECL 登录。

授权页面上的应用显示名称、Logo、发布者名称和发布者验证状态可以作为用户参考信息，但显示名称和 Logo 可以被其他 OAuth 应用仿冒；Publisher Verification 验证的是发布者组织身份，也不能单独证明某个 Client ID 属于 ECL。不得将名称完全匹配、发布者状态或权限列表中的任何单一信息描述为应用身份的密码学证明。

ECL 必须固定自己使用的 OAuth Client ID，并对自己构造的授权请求及收到的回调执行程序校验。用户可见的名称核对只能作为辅助提示，不得成为会话终止机制的替代品，也不得要求用户复制密码、授权码、访问令牌或刷新令牌。

### 8. 令牌与诊断信息的安全边界

授权码、PKCE verifier、访问令牌、刷新令牌、ID Token 及其他敏感认证材料不得写入普通日志、剪贴板、崩溃报告、普通配置或诊断附件。

会话终止日志可以记录会话内部标识、阶段、时间、非敏感异常类别和终止结果，但不得记录可重放或可兑换的认证材料。面向用户的错误信息应说明登录已取消、超时或因校验失败而终止，不应泄露秘密参数。

## 备选方案

### 方案 A：只依赖授权码自然过期

优点是实现简单，不需要额外会话治理。

缺点是无法及时阻止本地迟到回调、重复处理、令牌响应竞态或账户状态误提交；授权码自然过期也不等于 ECL 已经终止自己的会话。

不采用。

### 方案 B：只关闭 localhost 监听器

优点是能够停止后续本地回调请求。

缺点是无法阻止已经进入处理流程的回调、正在进行的令牌兑换或迟到响应更新账户状态；也没有清晰的会话终态语义。

不采用作为完整方案。关闭监听器只是终止操作的一部分。

### 方案 C：通过浏览器监控或系统级网络监听检测所有授权页面

优点是表面上可以尝试观察更多浏览器导航或网络活动。

缺点是需要额外权限，无法可靠覆盖不同浏览器、配置文件、进程和独立授权流程；会引入显著隐私成本、平台兼容性和维护负担，也无法可靠证明页面身份。

不采用。

### 方案 D：本地一次性会话 + 原子终止 + 迟到结果隔离

由 ECL 管理每次登录的独立会话；异常或取消时先使会话进入不可恢复的终止状态，再关闭监听器、取消后续工作、清理临时材料并丢弃迟到响应。

采用作为本 ADR 的核心方向。它直接解决 ECL 能控制的安全边界，不假定 ECL 能控制 Microsoft 服务端或用户浏览器中的独立授权流程。

## 后果

### 正面影响

- ECL 能够在检测到会话异常或用户取消时立即使本地登录会话失效。
- 迟到回调、重复回调和迟到令牌响应不能重新激活已终止会话。
- 登录会话之间的 PKCE 材料、state、回调监听器和结果处理相互隔离。
- 取消操作不再只是 UI 状态变化，而是具有明确安全语义的会话终止。
- 威胁模型聚焦于 ECL 实际能够检测和控制的范围，不会把同名应用误判成对现有 PKCE 会话的直接劫持。
- 不需要为了本 ADR 引入浏览器全局监控或改变已经可用的 localhost 注册配置。

### 代价与风险

- 需要严谨处理回调、令牌兑换、账户状态提交和终止操作之间的并发竞态。
- 关闭监听器或取消网络请求不保证 Microsoft 服务端没有处理已经发出的请求。
- 本地终止不能撤销独立 OAuth 应用已经取得的授权，也不能保证关闭浏览器中的授权页面。
- 本地回调端口仍可能遭受探测或拒绝服务；实现需要区分普通噪声与针对当前会话的有效性异常。
- 运行时内存清理受语言、运行时和对象生命周期限制，不能承诺所有临时秘密副本都被绝对即时擦除。

### 待验证事项

- 当前 ECL OAuth 实现中会话状态、PKCE verifier、state、回调监听器和令牌兑换任务的实际生命周期。
- 当前回调处理是否在所有异步阶段验证会话仍然有效。
- 当前实现是否存在令牌响应返回与账户凭据持久化之间的竞态。
- 当前 localhost 监听器的绑定接口、端口分配、路径处理、请求方法和关闭时机。
- 当前 Microsoft Entra 应用注册中的 localhost redirect URI 与实际 OAuth 库行为是否一致。
- 当前实现对重复回调、迟到回调、用户取消、超时、令牌兑换取消和服务端已处理请求的错误语义。

## 验收标准

本 ADR 当前为 Proposed。以下是未来实现评审的架构验收方向，不表示功能已经实现：

1. 每次 Microsoft 登录创建独立的一次性会话，且不同会话不共享 PKCE verifier、state 或回调监听器。
2. 用户取消、超时或明确的会话完整性异常能够使会话进入不可恢复的终止状态。
3. 终止状态优先于并发回调、令牌兑换完成回调和账户状态提交；终止后任何异步结果都不能使会话重新成功。
4. 终止时关闭本次 localhost 回调监听器，停止接受该会话的新请求。
5. 终止时取消尚未完成的令牌兑换；无法取消的迟到响应必须被丢弃，且不得持久化到账户凭据。
6. 终止时清理或释放本次会话的临时认证材料；诊断信息不包含授权码、verifier 或令牌。
7. 回调必须验证本次会话的 state、预期 redirect URI、PKCE 绑定及适用协议要求；重复回调不得重复兑换或提交。
8. 普通无关 HTTP 探测不会被误认为有效授权响应；安全校验失败的授权结果绝不进入成功路径。
9. 令牌兑换完成后、凭据提交前再次检查会话状态，保证取消与提交之间没有可利用的竞态。
10. 用户可见状态准确区分用户取消、超时、回调异常、协议校验失败、令牌兑换失败和成功。
11. 文档、日志和 UI 不得宣称本地终止能够让 Microsoft 服务器端授权交互立即过期，或撤销其他 OAuth 应用已经获得的权限。
12. 保持现有 PKCE + localhost loopback 登录架构；除非单独验证兼容性与安全收益，不因本 ADR 强制改用 127.0.0.1 或 [::1]。
13. 回调监听器仅绑定 loopback 接口，并在成功、终止或超时后关闭。
14. 普通启动、离线账户和其他不依赖本次 Microsoft 登录的功能不受影响。
