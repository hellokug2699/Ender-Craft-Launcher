# ADR 0015：按进程隔离游戏日志会话与诊断证据

- 状态：已采纳
- 日期：2026-11-01
- 范围：游戏进程生命周期、日志采集、崩溃恢复、诊断导出

## 背景

Minecraft 默认日志通常写入实例目录中的 `logs/latest.log`，并按配置轮转归档。但同一个实例可能同时运行多个游戏进程，不同实例也可能并行运行；日志文件本身并不天然具有进程身份。

此外，游戏崩溃、ECL 崩溃、系统崩溃或突然断电都可能发生在任意写入阶段。仅在游戏退出时复制 latest.log，既无法覆盖所有异常情况，也无法保证文件属于刚刚退出的进程。

## 决策

### 1. 每次进程启动创建独立会话

- 每次游戏进程启动分配唯一且不可变的 SessionId。
- 会话不等同于实例、PID、latest.log 或某个崩溃报告。
- 同一实例的多次启动必须创建不同会话；同一实例并发启动也不得覆盖或混合会话数据。
- 日志窗口关闭、游戏退出或 ECL 重启均不得自动删除会话证据。

### 2. 由统一服务管理会话生命周期

由 Core 中统一的游戏日志会话服务负责：

- 会话创建与持久化；
- 进程身份和生命周期跟踪；
- 日志与崩溃文件登记；
- ECL 重启后的恢复；
- 证据归属评估；
- 面向单次启动的诊断导出。

UI 只呈现会话和日志，不负责进程生命周期，也不得自行扫描目录并推断文件归属。

### 3. 会话数据必须可恢复

- 启动游戏进程前，先持久化初始 manifest 和 Starting 事件。
- 进程创建成功后，记录 PID、进程启动时间、可执行文件身份和工作目录。
- Manifest 采用临时文件写入后原子替换；生命周期事件采用带序号的追加式 journal。
- 恢复时允许忽略 journal 最后一条不完整记录，但必须保留此前有效记录。
- ECL 重启后，遗留在 Starting 或 Running 状态的会话应标记为 Interrupted 或 RecoveryPending，不得伪装成正常退出。
- 只有 PID、进程启动时间和可执行文件等身份信息足以匹配时才允许重新附着；PID 单独不足以证明进程身份。
- 恢复必须幂等，重复执行不得重复登记文件或破坏已有证据。

突然断电时只能提供有界的尽力恢复能力。关键生命周期转换应及时刷新；普通高频日志可以批量写入。不得承诺硬件、文件系统缓存或存储控制器故障下的绝对持久性。

### 4. 优先使用每会话独立游戏日志

对于经过验证支持的 Minecraft/Loader 配置，ECL 应为每次启动使用独立的日志配置，将游戏文件日志写入会话目录。

- 不得盲目覆盖整合包或用户自定义的 Log4j2 配置。
- 不得直接修改共享实例文件。
- 必须验证独立日志文件确实创建并收到内容；启动成功本身不代表隔离成功。
- 记录使用的配置、指纹、隔离方式和警告。
- 若无法安全隔离，则使用 stdout/stderr 等可用的会话级采集作为补充，并明确标记共享日志归属不确定。

### 5. latest.log 和轮转归档不是天然的进程证据

当只能获得实例级共享日志时：

- 记录启动前后的文件快照、大小、时间、文件身份及可用的哈希信息。
- 文件监视事件只能作为线索，不能代替前后状态核对。
- 可能由多个进程同时写入或轮转的 latest.log，不得声称属于某一个进程的完整日志。
- 轮转归档应按实际格式识别和读取，不得假设所有归档都是 ZIP。
- 无法可靠关联的文件应保留为未关联证据，而不是静默丢弃或错误归属。

### 6. 崩溃证据采用来源与置信度模型

诊断采集至少覆盖：

- JVM fatal error 文件，例如 `hs_err_pid*.log`；
- Minecraft 客户端崩溃报告；
- Minecraft 服务端崩溃报告；
- 当前游戏日志与可用的轮转归档；
- ECL 自身记录的进程、启动阶段和异常退出信息。

关联时综合路径、文件身份、时间、PID、进程信息、启动前后快照等证据，并标记归属置信度。不得仅凭“最新文件”或文件名认定归属。用户显式提供的 JVM 参数（例如 ErrorFile）不得被静默覆盖。

### 7. 诊断导出按单次会话组织

- 一次导出对应一个 SessionId。
- 包含该会话可获得的日志、崩溃证据、manifest、生命周期记录和证据关联信息。
- 明确列出缺失项、无法关联项、部分日志和恢复状态。
- 对导出内容进行必要的敏感信息脱敏，同时保留原始证据来源与哈希记录。
- 解包和打包过程必须防范路径穿越、恶意压缩包及异常解压大小；不得信任归档中的任意路径。

### 8. 历史保留与界面重置分离

新启动可以让 UI 默认聚焦最新会话，但这只是展示层行为：

- 不得因新启动而删除旧会话。
- 不得删除仍在运行或状态未知的会话。
- 物理清理必须由独立保留策略控制，并明确告知用户。
- 日志窗口关闭、游戏正常退出和 ECL 重启均不触发隐式清理。

## 后果

### 正面

- 同一实例的多次启动和并发进程拥有独立的会话身份。
- 游戏退出后和 ECL 重启后仍可查看历史日志。
- 诊断导出可以说明证据来自哪里、与目标进程的关联有多可靠。
- 异常中断不会被误记为正常退出。

### 代价与约束

- 需要维护会话索引、manifest、journal、恢复逻辑和证据库存。
- Minecraft/Loader/整合包的日志配置差异意味着无法保证所有环境都能实现文件日志隔离。
- 对共享日志必须接受并呈现归属不确定性。
- 持久化频率、日志量和磁盘占用需要平衡，并配套明确的保留策略。

## 详细设计

本 ADR 定义产品与架构决策。目录布局、字段清单、恢复步骤、日志隔离兼容性、文件关联算法和导出安全细节，见私有 Core 仓库的 Game Log Sessions and Diagnostic Export hint。

## 验收标准

1. 每次启动均生成独立 SessionId，同一实例并发运行不会互相覆盖。
2. 关闭日志窗口或游戏退出不会删除会话；ECL 重启后仍可查看历史记录。
3. 异常中断恢复幂等，PID 复用不会导致错误附着。
4. 共享日志的归属不确定性在 UI 与导出中明确标记。
5. 诊断导出限定于目标会话，并记录缺失、未关联及部分证据。
6. 自定义日志配置不会被未经验证地覆盖或修改。
