# ECL Media Engine

- Addition ID: `ecl.media-engine`
- Type: `Feature`
- Category: Media Processing
- Registry Status: `Proposed`
- Current Version: 尚未发布

## 概述

ECL Media Engine 是独立、可选的通用媒体处理 Addition，为用户和其他 Addition 提供图片、音频、视频的格式识别、读取、元数据提取、格式转换、基础编辑、预览与可视化能力。

图片处理方向包括尺寸调整、裁剪、旋转、拼接和批量处理；音频处理方向包括裁剪、分段、合并、试听与波形显示；视频处理方向包括尺寸调整、片段裁剪、合并、时间定位和播放预览。具体能力、格式和平台覆盖范围以经过验证的后端能力为准，不承诺全格式兼容或专业级 DAW/NLE 功能。

Media Engine 自身负责媒体能力发现、编辑/转换任务协调、预览数据生成和处理后端治理；具体编解码能力由经过许可、安全和兼容性审查的后端提供。它不属于 ECL Core 的启动依赖，也不进入 Minecraft 普通启动链。

本条目当前为 Proposed。登记不代表已经实现、通过格式兼容性验证或存在可下载资产。

## 临时工作区与源文件保护

- 所有编辑均在 Core 管理的独立临时工作区中执行。导入时创建独立工作副本；不得使用会让工作区写入穿透至源文件的硬链接或其他共享可变存储方式。
- 裁剪、合并、拆分、转换和预览均以工作区副本及其派生结果为输入；处理后端不得直接写入源文件。
- 预览应反映当前编辑状态对应的工作区结果，不得为了预览提前覆盖源文件。
- 用户可以导出为新文件，或在最终阶段明确确认后请求替换源文件。导出与破坏性替换必须是两个独立、清晰的操作。
- 替换前检查源文件身份和版本；源文件被外部修改、移动、替换或无法确认时，中止自动覆盖并要求用户重新决策。
- 破坏性替换必须具备安全替换/回退策略和失败恢复材料；无法保证安全的平台应禁用替换，但仍允许导出新文件。
- 多文件拆分/批量输出应有完整结果清单、冲突处理和失败报告；不得将非原子多文件写入宣称为整体原子事务。
- 异常退出后应识别未完成工作区并提供恢复、导出或放弃选择；不得无条件清理可能包含用户未完成工作的临时文件。
- Core 负责工作区生命周期、文件访问授权和最终提交；Media Engine 负责媒体处理。该工作区是任务级临时空间，不是新的 Addition，也不等同于玩家长期资料 Workspace。

## 功能范围

### 图片

- 常见图片格式识别、读取、元数据提取和格式转换。
- 尺寸/分辨率调整、裁剪、旋转、翻转。
- 多图片拼接/合并和批量处理。
- 透明通道及色彩信息处理，以具体格式和后端能力为准。

### 音频

- 常见音频格式识别、读取、元数据提取和格式转换。
- 裁剪、分段、合并、音量调整和基础淡入淡出。
- 音频试听与波形可视化，用于定位片段、识别静音区间和辅助编辑。
- 多音轨组合或基础混音可作为后续能力方向，不承诺专业级 DAW。

### 视频

- 常见视频容器/编码识别、读取、元数据提取和格式转换。
- 尺寸/分辨率调整、画面裁剪、片段截取和多个片段合并。
- 素材与结果播放预览、时间定位、关键帧/缩略图提取。
- 基础时间轴和音视频轨道操作可作为后续能力方向，不承诺专业级 NLE。
- 视频播放预览服务于媒体编辑与检查，不因此建立独立通用视频播放器 Addition。

具体格式和编码组合以经过验证的后端能力为准。扩展名不能作为内容真实性或可解码性的唯一依据；对未知、不支持、损坏、截断或部分支持的文件给出准确状态。

## 后端与依赖策略

- ECL 自主维护统一媒体能力抽象、后端治理、编辑/转换任务协调和预览集成，不从零重写通用编解码器。
- 不将 FFmpeg 或任何单一媒体框架设为强制依赖或架构核心。
- FFmpeg 仅是未来可独立评估的可选后端候选；当前不批准默认捆绑或强制依赖。
- 可评估成熟第三方库、平台原生媒体 API 或与 ECL 当前技术栈兼容的实现。
- 后端必须声明格式能力、读写/编辑能力、平台范围、依赖、许可证和限制；发布前完成代码、编解码器和分发义务审查。
- 不为单一功能无必要地引入额外语言运行时。确需原生库、独立进程或其他语言组件时，必须评估部署、调试、签名、升级和隔离成本。
- 图片、音频、视频及预览后端应按需交付/加载，避免仅使用某一类能力时下载全部媒体依赖。

## 安全与隐私边界

- 媒体文件及元数据均视为不可信输入。
- Core 授权资源访问并管理工作区；Media Engine 后端仅操作被明确授权的工作区输入与输出，不得直接修改源文件。
- 处理过程受 CPU、内存、临时磁盘、并发预算、取消、超时和失败恢复约束。
- 不得默认上传媒体内容、元数据、波形数据或缩略图。
- 不静默安装系统级编解码器，不修改系统媒体关联或用户环境。
- 后端若运行原生代码或外部进程，必须如实说明实际权限边界；普通进程隔离不等于完整 OS 沙箱。

## 不支持的平台保护措施绕过

Media Engine 面向普通公开格式和已获得合法处理授权的媒体内容：

- 不开发、内置、捆绑或自动下载用于绕过第三方平台 DRM、访问控制或技术保护措施的专用解密器。
- 不将 NCM 等平台专有加密封装解密视为普通格式转换能力。
- 第三方开源许可证不替代内容权利人或平台对技术保护措施的授权。
- 不支持的受保护格式明确报告 Unsupported / Not Supported，不尝试静默绕过。
- 不因文件无法解析就推断用户文件违法，也不妨碍用户导入普通标准媒体文件。

## 与其他 Additions 的关系

- ECL Music Player 可在未来选择性复用音频识别、解码或转换能力；基本音乐播放不得强制依赖完整 Media Engine。
- Resource Pack Studio、Map Art Studio、Shader Studio 等可按需复用图片或视频能力，其领域语义仍由各自 Addition 负责。
- Addition 间协作遵循 Core 受控机制，不直接 IPC 或共享内部对象。
- Required Additions：无。
- Optional Additions：无（未来消费者关系须单独登记，不代表当前存在运行时依赖）。
