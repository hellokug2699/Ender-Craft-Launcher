# ECL 数据处理说明

> 本文用来说明 ECL 自身会在本机产生和保存哪些数据、用户主动导出的诊断文件可能包含什么，以及使用第三方服务时的数据边界。它不是对 Windows、GitHub、网络运营商或内容平台的数据处理行为作出的承诺。

## 1. ECL 自身做什么

ECL 是运行在用户设备上的 Minecraft 启动器。为了完成实例管理、游戏启动、内容下载、登录和故障诊断，ECL 会在本机读取、生成或保存必要的数据，例如：

- **配置与实例信息：** 启动器设置、实例名称、Minecraft 版本、加载器和模组相关元数据。
- **账户与认证状态：** 为支持账户登录和后续访问而保存必要的认证数据。Windows 上的相关凭据保护机制以当前实现为准；不要把账户文件或令牌分享给他人。
- **运行日志：** 启动器运行时间、操作步骤、错误信息、版本信息、文件路径等诊断上下文。
- **游戏会话记录：** 游戏启动与退出时间、进程状态、Java 可执行文件及启动参数等，用于区分并诊断不同游戏进程的日志。
- **缓存和下载信息：** 为内容检索、下载和实例管理保存的本地缓存及元数据。

这些数据在本机生成或保存，不代表 ECL 会自动把它们上传给维护者。

## 2. ECL 不会主动做的事情

根据当前项目设计，ECL 不提供后台广告或用户画像功能，也没有主动遥测、自动上传日志或自动上传崩溃报告的设计。

ECL 不会因为用户启动或退出游戏，就自动向维护者发送游戏时间、模组列表、世界文件、截图或诊断包。诊断包和会话记录由用户主动导出；是否进一步分享，由用户决定。

这描述的是 ECL 自身的行为，不代表第三方平台、操作系统或网络服务不会依据其自身规则处理连接数据。

## 3. 用户主动导出的诊断文件

诊断文件是为了帮助用户或维护者定位问题而设计的。导出前请检查内容；分享前应确认接收方可信，并删除不希望披露的信息。

### 普通诊断包可能包含

- ECL 版本、操作系统与 .NET 信息；
- 实例元数据、Minecraft 与 Java 版本；
- 全局及实例设置；
- 最近的启动器日志、Minecraft 日志、崩溃报告；
- 安装失败诊断和启动 Java 计划。

普通诊断包不包含账户数据库文件。文本内容会尝试对访问令牌、密码、Authorization、Bearer token 和 URL 中的用户名/密码等内容进行脱敏。但脱敏不是对所有个人信息的保证，不能保证识别任意格式的秘密或用户生成内容。

### 游戏会话导出可能包含

- 会话创建、启动、运行和退出等事件及时间戳；
- 进程 ID、Java 可执行文件、工作目录和启动信息；
- 游戏标准输出、标准错误、崩溃报告及其他关联日志证据；
- 会话摘要和证据关联信息。

会话导出中的文本会经过秘密信息脱敏，但原始本地证据文件不会被改写。因此，导出内容仍可能包含玩家名称、本机用户名、文件路径、服务器地址、聊天文本、模组或整合包信息，以及其他由游戏、模组或用户输入产生的内容。时间戳也可能让接收者推断游戏运行的大致时间。

**导出不等于上传。** ECL 将文件写入用户指定或显示的本地位置；只有用户自行发送、上传或附加给 Issue/论坛/聊天时，接收方才会取得该文件。

## 4. 第三方服务

ECL 的部分功能需要连接第三方服务。用户使用这些功能时，请求会发送给相应服务；第三方可能依据自己的隐私政策、服务条款和技术配置处理连接信息。ECL 无法代表这些服务承诺其收集范围、日志保留期限或内部使用方式。

| 服务 | ECL 使用场景 | 数据边界 |
| --- | --- | --- |
| **Cloudflare** | ECL 的 CurseForge 代理基础设施等 | 请求经过 Cloudflare 基础设施时，Cloudflare 可能处理网络连接、请求和安全运行所需的数据。具体记录与保留由 Cloudflare 服务配置及其政策决定。 |
| **Modrinth** | 搜索、获取或下载 Modrinth 内容 | 请求会发送至 Modrinth 提供的服务或内容分发节点；相关请求数据由 Modrinth 及其所用基础设施按自身规则处理。 |
| **CurseForge / Overwolf** | 搜索、获取 CurseForge 内容；部分 API 请求经 ECL 的代理转发 | API 请求会经过代理基础设施并到达 CurseForge 服务。文件下载可能由其内容分发网络提供。CurseForge / Overwolf 与相关基础设施的数据处理不由 ECL 控制。 |
| **Microsoft / Xbox / Minecraft Services** | 支持的 Microsoft 账户认证及 Minecraft 服务访问 | 登录和授权流程会与 Microsoft、Xbox 或 Minecraft 服务交互；认证数据由相关服务按其规则处理。 |
| **GitHub** | 获取公开 Release、更新资产、项目源码和文档 | 访问 GitHub 时，GitHub 会处理其服务运行所需的请求信息；下载行为也可能关联到用户的 GitHub/网络访问环境。 |

上表描述的是 ECL 的服务依赖关系，不是对第三方实际收集字段的完整审计。第三方政策和基础设施可能变化，请以服务提供方当前公布的信息为准。

## 5. 网络连接与运营商

ECL 通过互联网访问上述服务。网络运营商、DNS 服务商、代理、CDN 或其他网络中间环节，可能依据其服务和所在地规则处理连接元数据，例如连接时间、目标服务、IP 地址或流量信息。HTTPS 可以保护传输内容免受普通链路窃听和篡改，但不意味着网络连接本身不可见，也不能约束第三方服务端如何处理收到的数据。

## 6. 用户可以做什么

- 分享日志或诊断包前，先打开 ZIP 检查文件列表和内容。
- 注意本机用户名、绝对路径、服务器地址、聊天内容、模组清单和游戏时间等信息。
- 不要公开分享账户数据库、访问令牌、密码、私钥或其他凭据。
- 只向可信的维护者或支持渠道提供确实需要的诊断材料。
- 不需要帮助排查问题时，可以不导出、不分享诊断文件；本地日志和会话数据可按 ECL 提供的管理功能自行清理。
- 对第三方服务的数据处理问题，请查看对应服务提供方的说明并直接向其咨询。

## 7. 说明范围

本文说明 ECL 当前项目设计与已记录功能中的数据处理行为，不构成对所有第三方服务、操作系统、网络运营商或用户设备的保证。具体实现可能随版本变化；如 ECL 将来新增遥测、自动上传、云同步或其他会向维护者/服务端发送用户数据的功能，应在启用前明确说明发送内容、目的和用户控制方式，并更新本文。
